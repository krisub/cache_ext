# Global Optimization Insights

## Successful Algorithmic Patterns

- **Multi-tier list architecture with network-adaptive scoring**: The current best program (Generation 1, score 304.65) and the closely-performing Generation 2 (score 302.10) both employ three separate lists (hot/warm/cold) with tier-based promotion logic, significantly outperforming the single-FIFO approach of Generation 0 (score 292.57). The multi-tier structure enables differentiated eviction strategies per tier, allowing conservative protection of hot folios while aggressively evicting cold data. This 12-point improvement (304.65 vs 292.57) demonstrates that architectural separation is more effective than unified list management with metadata-only tiering.

- **Adaptive time-window scaling based on TCP congestion metrics**: The current best program scales recency and working-set protection windows (50-150ms and 800ms-2s respectively) based on a composite congestion score derived from RTT, jitter, retransmissions, and congestion window pressure. This dynamic adaptation maintains strong performance across heterogeneous conditions: dual_small_vs_large throughput of 298.54 ops/sec and dual_congested throughput of 311.01 ops/sec. The congestion-aware windowing allows the policy to extend protection during high-latency periods (when cache misses are costly) while maintaining aggressive eviction during low-congestion phases, achieving balanced performance across both scenarios.

- **Composite scoring function with weighted factors**: The current best program's eviction callback uses a 1000-point scoring system combining recency (500pts), frequency (300pts), burst detection (200pts), and network congestion metrics (100pts), with tier-based bonuses (hot +150pts, warm +75pts). This multi-factor approach outperforms simpler heuristics: Generation 0's access-count-based tiering (threshold of 3) achieved 292.57, while the weighted scoring in Generation 1 achieved 304.65. The granular point allocation allows fine-grained trade-offs between competing objectives (recency vs. frequency vs. network cost), enabling the policy to adapt to workload characteristics without rigid thresholds.

- **Burst detection with inter-arrival timing**: The current best program detects request bursts by monitoring inter-arrival times between TCP packets (5ms threshold), triggering enhanced working-set protection during rapid request sequences. This mechanism provides responsive adaptation to workload phase changes without requiring explicit phase tagging or additional state. The burst detection complements the adaptive windowing by identifying transient high-load periods where cache retention is particularly valuable, contributing to the stable p99 latencies (165-231ms) across different network conditions.

## Implementation Insights

- **Three-tier list separation enables tier-specific eviction thresholds**: The current best program maintains separate `hot_list`, `warm_list`, and `cold_list` handles, each with a dedicated eviction callback (`bpf_evict_hot_cb`, `bpf_evict_warm_cb`, `bpf_evict_cold_cb`). The cold list uses a simple age-based threshold (evict if age > 500ms), the warm list uses a score threshold (evict if score < 200), and the hot list uses a conservative threshold (evict if score < 100). This separation allows the policy to apply progressively more aggressive eviction criteria as tier conservatism decreases, without requiring complex conditional logic within a single callback. The tier-specific thresholds are tuned to the expected access patterns of each tier, enabling efficient memory reclamation while protecting frequently-accessed data.

- **Congestion score computation aggregates multiple TCP metrics into a 0-1000 scale**: The current best program's `compute_congestion_score()` function combines RTT (0-400pts), jitter/mdev (0-250pts), retransmissions (0-200pts), and congestion window pressure (0-150pts) into a single normalized score. This aggregation allows downstream logic (adaptive window scaling, folio scoring) to use a single congestion metric rather than branching on multiple TCP variables. The point allocation reflects the relative importance of each factor: RTT dominates (400pts) because high latency makes cache misses expensive, while congestion window pressure is weighted lower (150pts) because it's a secondary indicator. The 1000-point scale provides sufficient granularity for the adaptive window calculations (e.g., `window += (BASE_WINDOW * congestion) / 1000`).

- **Adaptive window scaling uses linear interpolation between base and maximum values**: The current best program scales the recent-access window from 50ms (base) to 150ms (max) and the working-set window from 800ms (base) to 2s (max) using linear interpolation: `window = BASE_WINDOW + (BASE_WINDOW * congestion) / divisor`. This approach is computationally efficient (single multiplication and division) and provides predictable scaling behavior. The divisor differs between windows (1000 for recent, 500 for working-set) to achieve different scaling rates: the working-set window scales faster (1.6s range vs. 100ms range) because working-set protection is more critical during congestion. The linear scaling avoids non-linear artifacts and makes the policy behavior transparent and tunable.

- **Folio promotion logic moves folios between lists only on tier changes**: The current best program's `folio_accessed()` callback only removes and re-adds folios to different lists when `meta->access_tier > old_tier` (tier promotion). If the tier remains the same, the folio is moved to the head of its current list using `bpf_cache_ext_list_move(list, folio, false)` for MRU positioning. This optimization reduces list manipulation overhead: tier promotions (which require list removal and re-addition) occur only when access count crosses thresholds (1→2 for warm, 4+ for hot), while frequent re-accesses within the same tier only trigger head-moves. The threshold-based promotion (access_count >= 4 for hot, >= 2 for warm) ensures that transient accesses don't trigger expensive list operations, reducing CPU overhead while maintaining MRU ordering within tiers.
