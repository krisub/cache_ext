# Global Optimization Insights

## Successful Algorithmic Patterns

- **Tier-specific adaptive windowing with congestion-aware scaling achieves best performance**: The current best program (Generation 7, score 324.29) implements three independent time windows per tier (recent-access and working-set windows for cold/warm/hot), each scaling independently based on congestion metrics. This outperforms the simpler two-window approach in Generation 1 (score 304.65) by 19.64 points (+6.4%). The key innovation is tier-specific CONGESTION_SCALE factors (COLD: 500, WARM: 500, HOT: 250), allowing hot folios to scale window protection faster during congestion (2.4x multiplier at max congestion) while cold folios scale slower (1.6x multiplier). This differentiated scaling enables aggressive eviction of cold data even during congestion while protecting hot working sets, achieving superior throughput (314.32–334.92 ops/sec) and lower p99 latencies (167–246ms) compared to Generation 1's uniform scaling approach.

- **Access-count-based tier promotion with threshold-driven list movement reduces overhead**: The current best program promotes folios between tiers only when access_count crosses thresholds (≥2 for warm, ≥4 for hot), avoiding expensive list operations on every access. This threshold-based promotion strategy, combined with MRU head-moves within the same tier, achieves 324.29 compared to Generation 0's simpler access-count tiering (292.57, -31.72 points). The threshold approach (HOT_ACCESS_THRESHOLD=4) ensures that transient accesses don't trigger list removals/re-additions, reducing CPU overhead while maintaining precise tier classification. Within-tier MRU moves (via `bpf_cache_ext_list_move(list, folio, false)`) keep frequently-accessed folios at list heads without tier changes, enabling efficient recency-based eviction within each tier.

- **Burst detection with inter-arrival timing provides responsive workload phase adaptation**: The current best program detects request bursts by monitoring inter-packet arrival times (BURST_THRESHOLD_US=5000, i.e., 5ms), triggering enhanced working-set protection during rapid request sequences. This burst detection mechanism contributes to the 324.29 score by enabling the policy to identify transient high-load phases without explicit phase tagging or additional state. During bursts, the folio scoring function adds 0-200 points based on age within the working-set window, protecting the active working set from eviction. This responsive adaptation is particularly effective in the dual_congested workload (334.92 throughput), where burst detection helps distinguish between sustained congestion and transient packet bursts, enabling more precise cache retention decisions.

- **Composite scoring function with tier-specific bonuses balances multiple eviction objectives**: The current best program's `compute_folio_score()` function combines recency (0-500pts), frequency (0-300pts), burst protection (0-200pts), and congestion protection (0-100pts), with tier-specific bonuses (hot +150pts, warm +75pts). This multi-factor approach achieves 324.29, outperforming Generation 1's simpler scoring (304.65) by 19.64 points. The tier-specific bonuses (hot receives +150pts, warm receives +75pts) ensure that tier classification directly influences eviction decisions, making tier promotion meaningful. The point allocation reflects relative importance: recency dominates (500pts) because recent accesses indicate active use, while congestion protection is weighted lower (100pts) because it's a secondary indicator. The 1000-point scale provides sufficient granularity for tier-specific thresholds (hot: evict if score < 100, warm: evict if score < 200, cold: age-based), enabling precise control over eviction aggressiveness per tier.
