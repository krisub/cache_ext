- **Tier-specific adaptive windowing with independent congestion scaling achieves the highest performance (324.29) when combined with precise threshold tuning**: The current best program (Generation 7, score 324.29) implements six independent time window constants (BASE_RECENT_COLD_NS=30ms, BASE_RECENT_WARM_NS=50ms, BASE_RECENT_HOT_NS=100ms, BASE_WORKING_SET_COLD_NS=400ms, BASE_WORKING_SET_WARM_NS=800ms, BASE_WORKING_SET_HOT_NS=1.2s) with tier-specific congestion scaling factors (COLD: 500, WARM: 500, HOT: 250). This architecture achieves 324.29 combined harmonic mean with strong performance across both small-vs-large (314.32 throughput) and congested (334.92 throughput) workloads. The key differentiator from lower-performing programs (Generation 14, score 311.40; Generation 18, score 310.43; Generation 19, score 309.74) is that Generation 7 uses identical window constants and scaling factors, yet achieves 12.89–14.86 points higher performance, indicating that the specific threshold values and their application within the scoring function are critical. The tier-specific windows reflect expected access patterns: cold folios use aggressive windows (30ms recent, 400ms working-set) enabling rapid eviction, while hot folios use protective windows (100ms recent, 1.2s working-set) retaining frequently-accessed data. The maximum caps (60ms, 150ms, 300ms for recent; 800ms, 1.6s, 2.4s for working-set) prevent excessive expansion during extreme congestion while maintaining responsiveness.

- **Linear recency scoring with logarithmic frequency bonuses and tier-specific protection bonuses outperforms exponential decay approaches**: Generation 7 (score 324.29) implements linear recency decay (500 points linearly declining from recent window to 0), logarithmic frequency bonuses (1→50pts, 2→100pts, 3→150pts, 4+→300pts), and tier-specific protection bonuses (hot +150pts, warm +75pts), achieving the highest performance. This contrasts with exponential decay implementations (Generations 9, 13) which achieve 317.38 and 309.87 respectively, representing regressions of 6.91 and 14.42 points (-2.1% and -4.4%). The linear recency approach provides clear discriminative power: folios accessed within the recent window receive proportional protection based on recency, while the logarithmic frequency bonus prevents transient accesses from inflating scores. The tier-specific bonuses (hot +150, warm +75, cold +0) directly encode tier importance into the scoring function, enabling the eviction callbacks to use simple threshold comparisons (cold: age > 500ms, warm: score < 200, hot: score < 100) without complex conditional logic. Generation 7's implementation explicitly states "linear decay from 500 (just accessed) to 0 (beyond recent window)" and "logarithmic: access_count 1→50, 2→100, 3→150, 4+→300," confirming that the linear-logarithmic combination is the key differentiator from exponential approaches.

- **Burst detection with inter-arrival timing (5ms threshold) provides consistent 5–20 point performance improvement when properly integrated into scoring**: All high-performing programs (Generations 7, 8, 10, 11, 14, 16, 18, 19) implement burst detection via inter-packet arrival times with BURST_THRESHOLD_US=5000 (5ms), achieving scores of 309.74–334.92. Generation 7 (score 324.29) implements burst detection that adds 0–200 points based on age within the working-set window during bursts, contributing approximately 5–20 points of improvement compared to Generation 1 (score 304.65) which lacks burst detection. The burst detection mechanism is triggered when `(now - net_prev_packet_ts) < 5000000ULL`, identifying rapid request sequences that indicate active working-set phases. During bursts, the scoring function applies enhanced working-set protection: `if (in_burst && age_ns < working_set_window) { score += 200 - (200 * age_ns) / working_set_window; }`, providing linear decay from 200 points (just accessed) to 0 (beyond working-set window). This burst-aware scoring prevents premature eviction of pages accessed during high-throughput periods, protecting working-set integrity. The consistency of burst detection across all high-performing programs (324.29–334.92 range) demonstrates that the 5ms threshold is well-calibrated for the monitored workloads, though the specific integration into the scoring function (how burst signals are weighted relative to recency and frequency) remains critical for achieving maximum performance.
