<DESCRIPTION>
The current program uses a single adaptive recency window (`get_adaptive_recent_window`) that scales uniformly across all tiers. However, the recommendation highlights that we should use **tier-specific recency window scaling with different congestion multipliers**.

The key insight is:
- **Cold folios** should have a shorter, more aggressive recency window that scales faster with congestion, allowing aggressive eviction of cold pages while still protecting them during congestion.
- **Warm folios** should have a moderate recency window that balances protection with eviction.
- **Hot folios** should have a longer, more conservative recency window that scales slower with congestion, ensuring the working set is heavily protected even at low congestion.

Currently, the cold_list callback uses a fixed 500ms threshold regardless of congestion state. By making this tier-aware and congestion-adaptive, we can:
1. Evict cold pages more aggressively in low-congestion periods (free up memory faster)
2. Still protect cold pages during high congestion (avoid I/O thrashing)
3. Protect warm and hot pages more aggressively, which are more likely to be accessed again

This should improve throughput by reducing memory waste on cold folios while protecting the working set better under various network conditions.

**Changes:**
1. Add three separate helper functions for tier-specific recency windows
2. Modify `bpf_evict_cold_cb` to use aggressive cold-specific window that scales faster
3. Update the warm and hot callbacks to use tier-specific windows
</DESCRIPTION>

static __always_inline u64 get_adaptive_recent_window(u32 congestion) {
    // Scale from BASE_RECENT_ACCESS_NS (50ms) to 150ms based on congestion
    // High congestion → wider window to protect recency
    u64 window = BASE_RECENT_ACCESS_NS;
    window += (BASE_RECENT_ACCESS_NS * congestion) / 1000;  // add 0-50ms
    return window;
}

// Cold tier: aggressive window, scales faster with congestion (30-200ms)
static __always_inline u64 get_adaptive_recent_window_cold(u32 congestion) {
    // Base 30ms, scale to 200ms at max congestion
    // Scale factor: 5.67x from base at high congestion
    u64 base = 30000000ULL;   // 30ms base
    u64 window = base + (170000000ULL * congestion) / 1000;  // add 0-170ms
    return (window > 200000000ULL) ? 200000000ULL : window;
}

// Warm tier: moderate window, moderate scale (80-400ms)
static __always_inline u64 get_adaptive_recent_window_warm(u32 congestion) {
    // Base 80ms, scale to 400ms at max congestion
    u64 base = 80000000ULL;   // 80ms base
    u64 window = base + (320000000ULL * congestion) / 1000;  // add 0-320ms
    return (window > 400000000ULL) ? 400000000ULL : window;
}

// Hot tier: conservative window, slow scale (100-500ms)
static __always_inline u64 get_adaptive_recent_window_hot(u32 congestion) {
    // Base 100ms, scale to 500ms at max congestion

        return CACHE_EXT_EVICT_NODE;

    // Cold list: evict cold folios that haven't been accessed recently
