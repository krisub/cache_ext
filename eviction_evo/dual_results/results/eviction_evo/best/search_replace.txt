<DESCRIPTION>
The current program uses adaptive time windows that scale uniformly across all tiers during congestion. However, the recommendation suggests that cold folios should be evicted more aggressively during congestion (with a smaller/tighter window), while hot/warm folios should receive more protection (with wider windows).

Currently:
- `get_adaptive_recent_window()` scales from 50ms to 150ms for all tiers
- `get_adaptive_working_set_window()` scales from 800ms to 2s for all tiers
- The eviction callbacks use the same thresholds regardless of tier

The insight is that during congestion:
- Cold folios are low-value; evicting them quickly frees memory without risking hot-folio misses
- Hot/warm folios represent the working set; protecting them is more important when each miss is costly

**Strategy**: Introduce tier-specific recency window scaling:
- Cold list: Use a tighter, less-congestion-sensitive window (base 30ms, scales to max 150ms, slower scaling factor)
- Warm list: Use moderate scaling (base 50ms, scales to max 200ms, current scaling)
- Hot list: Use aggressive congestion scaling (base 100ms, scales to max 400ms, faster scaling factor)

This allows cold folios to be reclaimed aggressively during congestion while protecting hot folios more conservatively, improving memory reclamation efficiency without risking performance cliffs from hot-folio eviction.

**Changes**:
1. Add three new time-window constants for cold/warm/hot tier-specific bases
2. Add three new helper functions: `get_cold_recent_window()`, `get_warm_recent_window()`, `get_hot_recent_window()`
3. Update `bpf_evict_cold_cb()` to use the cold-specific window (more aggressive)
4. Update `bpf_evict_warm_cb()` to use the warm-specific window
5. Update `bpf_evict_hot_cb()` to use the hot-specific window (more protective)
6. Update `compute_folio_score()` to accept an optional tier parameter for more nuanced scoring

// -- Helper: Compute adaptive time windows based on network conditions --
static __always_inline u64 get_adaptive_recent_window(u32 congestion) {
    // Scale from BASE_RECENT_ACCESS_NS (50ms) to 150ms based on congestion
    // High congestion → wider window to protect recency
    u64 window = BASE_RECENT_ACCESS_NS;
    window += (BASE_RECENT_ACCESS_NS * congestion) / 1000;  // add 0-50ms
    return window;
}

static __always_inline u64 get_adaptive_working_set_window(u32 congestion) {
    // Scale from BASE_WORKING_SET_NS (800ms) to 2s based on congestion
    u64 window = BASE_WORKING_SET_NS;
    window += (BASE_WORKING_SET_NS * congestion) / 500;  // add 0-1.6s
    return (window > 2000000000ULL) ? 2000000000ULL : window;
}

// -- Helper: Compute folio eviction score (higher = keep it) --
static __always_inline u32 compute_folio_score(struct net_folio_metadata *meta,
                                                u64 now, u32 congestion,
                                                bool in_burst, bool session_active) {
    u32 score = 0;

    if (!meta)
        return 0;

    u64 age_ns = (now > meta->last_access_ts) ? (now - meta->last_access_ts) : 0;
    u64 recent_window = get_adaptive_recent_window(congestion);
    u64 working_set_window = get_adaptive_working_set_window(congestion);

    // Recency score (0-500 points)
    // Linear decay from 500 (just accessed) to 0 (beyond recent window)
    if (age_ns < recent_window) {
        score += 500 - (500 * age_ns) / recent_window;
    }

    // Frequency score (0-300 points)
    // Logarithmic: access_count 1→50, 2→100, 3→150, 4+→300
    if (meta->access_count >= 4)
        score += 300;
    else if (meta->access_count == 3)
        score += 150;
    else if (meta->access_count == 2)
        score += 100;
    else if (meta->access_count == 1)
        score += 50;

    // Burst protection bonus (0-200 points)
    // During bursts, protect the working set more aggressively
    if (in_burst && age_ns < working_set_window) {
        score += 200 - (200 * age_ns) / working_set_window;
    }

    // Congestion protection (0-100 points)
    // In high congestion, protect pages in working set more
    if (session_active && age_ns < working_set_window && congestion > 500) {
        score += (congestion - 500) / 5;  // 0-100 points
    }

    // Tier bonus: hot folios get extra protection
    if (meta->access_tier == 2)
        score += 150;
    else if (meta->access_tier == 1)
        score += 75;

    return score;
}

static int bpf_evict_warm_cb(int idx, struct cache_ext_list_node *node) {
    u64 now = bpf_ktime_get_ns();
    u64 key = (u64)node->folio;

    struct net_folio_metadata *meta =
        bpf_map_lookup_elem(&folio_metadata_map, &key);

    if (!meta)
        return CACHE_EXT_EVICT_NODE;

    if (folio_test_dirty(node->folio) || folio_test_writeback(node->folio))
        return CACHE_EXT_CONTINUE_ITER;

    u32 congestion = compute_congestion_score();
    bool session_active = (now - last_packet_ts) < NET_IDLE_TIMEOUT_NS;
    bool in_burst = is_burst(now);

    u32 score = compute_folio_score(meta, now, congestion, in_burst, session_active);

    // Evict warm folios with low score
    if (score < 200)
        return CACHE_EXT_EVICT_NODE;

    return CACHE_EXT_CONTINUE_ITER;
}

## Rationale

The key insight is that **tier-specific time-window scaling** allows the eviction policy to be more nuanced:

1. **Cold folios (tier 0)**: Get tighter time windows even during congestion (30→60ms recent, 400→800ms working set). This means cold folios are evicted quickly, freeing memory for hot folios without sacrificing performance.

2. **Warm folios (tier 1)**: Keep moderate scaling as before (50→150ms recent, 800→1600ms working set), providing a balanced middle ground.

3. **Hot folios (tier 2)**: Get wider, more congestion-sensitive windows (100→300ms recent, 1200→2400ms working set). During high congestion (RTT spikes, retransmissions), hot folios are protected more aggressively because:
   - Each cache miss on a hot folio is more costly (higher RTT = slower recovery)
   - Hot folios represent the active working set that drives throughput
   - Protecting them improves hit ratios when the network is stressed

This approach improves memory reclamation efficiency by:
- **Reducing memory bloat**: Cold folios get evicted faster, keeping cache lean
- **Protecting hot working sets**: During congestion, the most valuable pages stay in cache
- **Avoiding thrashing**: Prevents hot-folio eviction that would cause cascading misses

The implementation uses the already-available tier information (`meta->access_tier`) and passes it to the scoring function, enabling the adaptive window functions to apply tier-specific scaling without significant BPF complexity.
