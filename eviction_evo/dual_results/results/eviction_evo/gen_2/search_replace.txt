network_adaptive_thresholds
</NAME>

<DESCRIPTION>
The current policy uses fixed time thresholds (100ms for recent access, 1s for working set) regardless of network conditions. This is suboptimal because:

1. When network RTT is high (e.g., in dual_congested with 2-5ms delays), cache misses are more expensive, so we should protect pages more aggressively (longer working set window).
2. When the network is congested (high retransmissions, low cwnd), we should be more conservative about eviction.
3. The inter-arrival time between requests can indicate burst vs. steady-state behavior.

I'll introduce adaptive thresholds that scale based on:
- RTT (net_srtt_us): Higher RTT → longer protection windows
- Network congestion (net_lost, net_retrans_out): More congestion → more aggressive protection
- Request rate (inter-arrival time): Faster requests → tighter working set

This should improve performance especially on dual_congested where network conditions vary significantly.
</DESCRIPTION>

// Network-adaptive scaling factors
#define RTT_SCALE_FACTOR 8        // Scale protection by RTT / 1ms
#define CONGESTION_BOOST 2        // Multiply protection when congested
#define BURST_THRESHOLD_NS 50000000ULL  // 50ms inter-arrival = burst

// Helper: compute adaptive working set window based on network state
static __always_inline u64 get_adaptive_working_set_ns(void)
{
    u64 base = BASE_WORKING_SET_NS;

    // Scale by RTT: higher RTT = more expensive misses = longer protection
    // net_srtt_us is in microseconds, divide by 8 to get true RTT
    u32 rtt_us = net_srtt_us >> 3;
    if (rtt_us > 1000) {  // > 1ms RTT
        u64 rtt_multiplier = (rtt_us / 1000);  // RTT in ms
        if (rtt_multiplier > RTT_SCALE_FACTOR)
            rtt_multiplier = RTT_SCALE_FACTOR;
        base = base * (1 + rtt_multiplier) / 2;  // Scale up to 4.5x
    }

    // Boost protection during network congestion
    if (net_lost > 0 || net_retrans_out > 0) {
        base *= CONGESTION_BOOST;
    }

    // Detect burst mode: if requests are coming fast, tighten working set
    u64 inter_arrival = last_packet_ts - net_prev_packet_ts;
    if (inter_arrival > 0 && inter_arrival < BURST_THRESHOLD_NS) {
        base = base * 3 / 2;  // 1.5x during bursts
    }

    return base;
}

frequency_aware_promotion
</NAME>

<DESCRIPTION>
The current policy moves all accessed folios to the head of the list (MRU), which can cause thrashing when there are sequential scans mixed with random accesses. Research on ARC and LIRS shows that frequency information should influence promotion decisions.

I'll modify folio_accessed to only promote to head if the folio is "warm" or "hot" (access_count >= 2). Cold folios (first or second access) will be added/moved to tail instead, preventing them from evicting truly hot pages. This implements a simple frequency-aware promotion strategy.

This should help especially in dual_small_vs_large where one client does sequential scans (uniform distribution) while another does random reads (zipfian).
</DESCRIPTION>

<DESCRIPTION>
The current policy doesn't consider the congestion window (cwnd) when deciding eviction aggressiveness. When cwnd is small relative to packets_out, the network is bottlenecked and we should avoid causing additional I/O that would further congest the network.

I'll add logic to detect when the network is at capacity (packets_out close to snd_cwnd) and in that state, be even more conservative about evicting pages. This is particularly relevant for dual_congested where bandwidth limits are enforced.

Additionally, I'll track whether we're in slow-start (cwnd < ssthresh) vs congestion avoidance, as these phases have different characteristics.
</DESCRIPTION>

These changes implement a network-adaptive eviction policy that:

1. **Scales protection windows based on RTT**: Higher latency networks get longer protection windows since cache misses are more expensive
2. **Detects and responds to congestion**: Uses packet loss, retransmissions, and cwnd utilization to be more conservative during network stress
3. **Adapts to request bursts**: Detects fast inter-arrival times and adjusts working set accordingly
4. **Implements frequency-aware promotion**: Prevents cold pages from polluting the hot end of the LRU list
5. **Considers network capacity**: When the network is saturated (high cwnd utilization), avoids evictions that would cause I/O

These improvements should particularly help on dual_congested where network conditions vary significantly, while maintaining good performance on dual_small_vs_large by better handling the mixed workload patterns.
