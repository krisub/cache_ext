## Root Cause Analysis

The current `apply_access_count_decay()` function decays access_count by 1 whenever age exceeds the decay window. This is problematic because:

1. **During bursts**: The fast reader in `dual_small_vs_large` generates frequent accesses, but if there's any gap > decay_window, the access_count drops
2. **Decay window too aggressive**: 500ms base with tier scaling means even hot folios lose frequency info quickly
3. **Decay happens on every access**: The decay is applied every time a folio is accessed, causing cascading degradation

I'll implement a more conservative decay strategy that:
1. **Disables decay during bursts** (when requests arrive frequently)
2. **Uses exponential decay** instead of linear (1 point per window) to be gentler
3. **Increases decay window** to be less aggressive
4. **Protects high-frequency folios** from decay when in active session
