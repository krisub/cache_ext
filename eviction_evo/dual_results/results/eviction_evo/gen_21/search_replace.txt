<DESCRIPTION>
The current best program (Generation 7, score 324.29) uses tier-specific recency windows that expand with congestion but doesn't adapt them based on burst detection. Looking at the performance metrics, the current program (score 310.27) introduced access count decay which may be interfering with the burst protection mechanism.

The key insight is that during sustained burst phases (multiple consecutive packets within 5ms), the working set is actively being accessed and we should tighten recency windows to evict stale pages more aggressively. This is the opposite of what happens during congestion - bursts indicate high throughput potential, so we should be more aggressive about reclaiming memory from pages that aren't part of the active working set.

Specifically, I propose:
1. Track burst duration (consecutive burst packets) in a static variable within the EVOLVE-BLOCK
2. Update the burst counter in the eviction callbacks (we have access to timestamps there)
3. When we detect sustained burst phases, reduce the cold tier recency window by 30% and warm tier by 20%

This directly addresses the recommendation by making recency windows adaptive to sustained burst phases, enabling more aggressive eviction during high-throughput periods while maintaining protection during congestion spikes.

// -- Helper: Update burst tracking state ---
// Updates consecutive_burst_packets based on current burst status
static __always_inline void update_burst_tracking(u64 now) {
    if (last_burst_check_ts == 0) {
        last_burst_check_ts = now;
        consecutive_burst_packets = 0;
        return;
    }

    u64 time_since_last_check = (now > last_burst_check_ts) ?
        (now - last_burst_check_ts) : 0;

    // Update burst counter based on inter-arrival time
    if (time_since_last_check < 5000000ULL) {  // within 5ms burst threshold
        if (consecutive_burst_packets < 20)  // cap at 20
            consecutive_burst_packets += 1;
    } else {
        // Reset if gap exceeds burst threshold
        consecutive_burst_packets = 0;
    }

    last_burst_check_ts = now;
}

    // Map consecutive_burst_packets to 0-1000 scale

        return 0;
