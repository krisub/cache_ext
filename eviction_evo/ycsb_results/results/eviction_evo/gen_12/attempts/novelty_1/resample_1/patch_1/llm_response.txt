congestion_aware_working_set_shrinking
</NAME>

<DESCRIPTION>
The recommendation suggests adding congestion-aware working-set window shrinking during loss events. Currently, `get_adaptive_working_set_ns()` only expands during bursts but doesn't shrink during congestion. When `net_lost > 0` or `net_retrans_out > 0`, we should reduce WORKING_SET_NS_BASE from 500ms to 250ms to focus eviction on the most-recently-accessed pages and reduce cache pollution from older working-set members.

This complements the existing congestion-aware RECENT_ACCESS_NS shrinking (already proven effective) and follows the pattern that congestion should trigger protective mode by tightening the working set window. The rationale is:

1. During congestion, each cache miss is more expensive (higher latency, potential retransmissions)
2. By shrinking the working set window, we evict older members of the working set more aggressively
3. This frees cache space for the truly hot, recently-accessed pages
4. This should particularly help YCSB-D (temporal locality workload) which currently scores 146,870.89 ops/sec

The change is minimal and surgical: modify `get_adaptive_working_set_ns()` to check for congestion and return a tighter window when congestion is detected, similar to how `get_adaptive_recent_access_ns()` already does this.
</DESCRIPTION>

static __always_inline u64 get_adaptive_working_set_ns(void)
{
    u64 threshold = WORKING_SET_NS_BASE;

    // Detect network congestion: shrink working set window during loss events
    bool is_congested = (net_lost > 0) || (net_retrans_out > 0);
    if (is_congested) {
        // During congestion, tighten working set to focus on hottest pages
        threshold = threshold / 2;  // 250 ms (from 500 ms)
        return threshold;
