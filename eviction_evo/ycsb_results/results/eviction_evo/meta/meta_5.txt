# Optimization Insights Analysis

## Successful Algorithmic Patterns

- **Adaptive threshold modulation based on network congestion state** (Current Best: Gen 3, Score 270.98): The decay_and_scan_detection program successfully implements dynamic window shrinking during congestion/high-RTT (halving RECENT_ACCESS_NS from 100ms to 50ms) and expansion during burst detection (1.5x working-set expansion). This adaptive approach outperforms the static threshold strategy in Gen 0 (267.06) by 1.4%, demonstrating that coupling eviction decisions to real-time network metrics yields measurable improvements. The key insight is that congestion detection (via net_lost > 0 or net_retrans_out > 0) should trigger protective mode for hot pages, while burst detection (smoothed inter-arrival < 10ms) should expand working-set retention.

- **Time-decay of access counts to prevent stale hot classification** (Current Best: Gen 3, Score 270.98): The implementation of ACCESS_DECAY_HALF_LIFE_NS (500ms) ensures that folios don't remain classified as "hot" indefinitely. This prevents cache pollution from pages that were frequently accessed in the past but are no longer relevant. Gen 3 achieves 270.98 vs Gen 1's 268.76 (+0.8%), with Gen 3's decay mechanism enabling more aggressive cold-page eviction while maintaining protection for genuinely active working sets. The decay function (halving access count every 500ms) provides a principled way to age out stale metadata without requiring explicit cleanup.

- **Multi-tier protection logic with network session awareness** (Current Best: Gen 3, Score 270.98): The strategy of protecting very_hot folios (access_count ≥ 5) only when session_active AND recently_used, combined with separate protection for hot folios (access_count ≥ 3) and working-set folios during active sessions, creates a nuanced eviction hierarchy. This layered approach outperforms simpler binary hot/cold classification (Gen 0: 267.06) by allowing fine-grained retention decisions. The session_active detection via NET_IDLE_TIMEOUT_NS (5s) ensures that protection windows collapse during idle periods, enabling aggressive eviction of stale pages.

- **Smoothed burst detection via exponential smoothing** (Current Best: Gen 3, Score 270.98): Rather than reacting to instantaneous inter-arrival times, the program maintains smoothed_inter_arrival_ns updated with 7/8 weight on history and 1/8 weight on new measurements. This prevents false-positive burst detection from single fast packets and enables stable working-set expansion decisions. The smoothing factor (BURST_SMOOTH_SHIFT = 3, equivalent to 1/8 alpha) balances responsiveness with stability, contributing to consistent performance across diverse YCSB workloads (A-F all passing validation).

## Implementation Insights

- **Effective use of exponential smoothing for burst detection** (Current Best: Gen 3): The smoothed_inter_arrival_ns global is updated on every folio_added and folio_accessed call using the formula `(smoothed_inter_arrival_ns * 7) / 8 + (inter_arrival * 1) / 8`. This 7/8 weighting provides low-pass filtering that prevents single fast packets from triggering false burst detection. The burst threshold comparison (smoothed_inter_arrival_ns < BURST_THRESHOLD_US * 1000) then gates a 1.5x working-set expansion. This pattern is more robust than raw inter-arrival comparisons and contributes to stable performance across all 8 validation traces.

- **Decayed access count computation with loop-based half-life decay** (Current Best: Gen 3): The get_effective_access_count() helper implements decay by repeatedly dividing the access count by 2 for each ACCESS_DECAY_HALF_LIFE_NS period that has elapsed. This approach avoids floating-point arithmetic and provides predictable, verifiable decay behavior. For example, a folio with access_count=8 accessed 1 second ago (with 500ms half-life) would have effective_accesses=2, correctly reflecting that the folio is no longer "hot." This decay is then used in tier classification (hot if eff_count ≥ 3, warm if ≥ 2), ensuring that tier decisions reflect recent behavior rather than historical access patterns.

- **Layered protection hierarchy with session-aware gating** (Current Best: Gen 3): The bpf_evict_cb callback implements a multi-level protection strategy: (1) very_hot folios protected only if session_active AND recently_used, (2) hot folios protected if recently_used, (3) working-set folios protected if session_active AND in_working_set, (4) congestion-aware protection for hot pages, (5) catch-all protection for recently_used folios. This hierarchy ensures that protection is proportional to both access frequency and network state, avoiding over-retention of stale pages while maintaining cache hits for active working sets. The session_active gate (now - last_packet_ts < NET_IDLE_TIMEOUT_NS) is particularly effective at collapsing protection windows during idle periods.

- **Proper list management with folio_evicted cleanup** (Current Best: Gen 3): The evolved_folio_evicted callback explicitly calls bpf_cache_ext_list_del(folio) BEFORE bpf_map_delete_elem(), ensuring that the folio is removed from main_list before its metadata is deleted. This ordering prevents kernel memory corruption (GPF in userspace) that would occur if the eviction iterator held a dangling folio pointer. The feedback explicitly notes "Proper cleanup in folio_evicted (list deletion before metadata removal) prevents kernel memory corruption, demonstrating correct BPF API usage." This pattern is critical for correctness and is consistently applied across all passing programs (Gen 0, 1, 3, 4).

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

# Actionable Recommendations for Future Program Mutations

1. **Implement adaptive access count decay rates based on network state** — Currently, ACCESS_DECAY_HALF_LIFE_NS is fixed at 500ms regardless of network conditions. During high-congestion periods (net_lost > 0 or net_retrans_out > 0), accelerate decay to 250ms to more aggressively age out stale hot classifications and free cache for current working sets. During low-latency bursts (smoothed_inter_arrival_ns < 5ms), extend decay to 750ms to retain hot pages longer since the network can sustain rapid re-accesses. This adaptive decay directly extends Gen 3's successful decay mechanism while coupling it to real-time network state, similar to how adaptive thresholds improved from Gen 0 to Gen 3.

2. **Introduce a "promotion" tier for very-hot folios with multi-level protection windows** — Currently, very_hot folios (access_count ≥ 5) are protected only if session_active AND recently_used, which may under-protect pages that are genuinely critical. Implement a separate promotion list for folios that reach access_count ≥ 7 (after decay), protecting them with a longer window (e.g., 200ms instead of 100ms) even during moderate congestion. Use bpf_cache_ext_list_iterate_extended to move promoted folios to a continue_list during eviction, creating a two-tier protection hierarchy that mirrors the multi-tier success pattern already proven in Gen 3.

3. **Refine burst detection to account for RTT-relative inter-arrival times** — The current BURST_THRESHOLD_US (10ms) is absolute and doesn't account for network latency; on high-RTT networks (net_srtt_us > 50ms), 10ms inter-arrivals are not actually "bursts." Compute a dynamic burst threshold as `max(10ms, net_srtt_us / 4)` so that burst detection scales with observed RTT. This prevents false-positive burst detection on high-latency networks (which would over-expand working sets and hurt YCSB-A/B/C performance) while maintaining sensitivity on low-latency networks, directly addressing the weak read-heavy workload performance (YCSB-A: 600.43 ops/sec) noted in the performance analysis.

4. **Add congestion-aware working-set window shrinking during loss events** — Currently, get_adaptive_working_set_ns() only expands during bursts but doesn't shrink during congestion. When net_lost > 0 or net_retrans_out > 0, reduce WORKING_SET_NS_BASE from 1s to 500ms to focus eviction on the most-recently-accessed pages and reduce cache pollution from older working-set members. This complements the existing congestion-aware RECENT_ACCESS_NS shrinking and follows the pattern that congestion should trigger protective mode (as noted in the successful patterns analysis), potentially improving YCSB-D performance further while maintaining read-heavy workload stability.

5. **Implement access-count-weighted recency scoring to break ties in eviction decisions** — Currently, the eviction callback uses binary protection rules (protect if hot AND recently_used, else evict), which doesn't differentiate between a folio with access_count=3 and one with access_count=10 when both are equally recent. Introduce a scoring function that combines decayed access count and recency: `score = effective_accesses * 10 + (1 - (now - last_access_ts) / recent_access_ns) * 100`, then evict only folios with score < threshold (e.g., 50). This creates a continuous ranking rather than binary decisions, allowing the eviction iterator to make more nuanced choices and potentially improve harmonic mean score by 0.5–1% by better handling the boundary cases between tiers.
