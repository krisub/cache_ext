# Optimization Insights Analysis

## Successful Algorithmic Patterns

- **Adaptive decay windows coupled with network congestion detection** (Current Best: Gen 8, Score 275.99): The adaptive_decay_network_aware program implements three distinct decay windows—normal (500ms), congestion-accelerated (250ms), and burst-extended (750ms)—selected dynamically based on real-time network state. This outperforms Gen 3's static 500ms decay (270.98) by 1.9%, demonstrating that decay aggressiveness should scale with network conditions. During congestion (net_lost > 0 or net_retrans_out > 0), the 250ms window accelerates eviction of stale pages to free cache for the current working set; during bursts (smoothed_inter_arrival_ns < 5ms), the 750ms window extends retention to protect hot pages during traffic spikes. The key insight is that a single fixed decay window cannot simultaneously handle congestion (which requires aggressive aging) and bursts (which require conservative aging), whereas adaptive windows achieve both.

- **Smoothed inter-arrival time for burst detection with exponential filtering** (Current Best: Gen 8, Score 275.99): The program maintains smoothed_inter_arrival_ns updated via exponential smoothing (7/8 weight on history, 1/8 on new measurement) rather than reacting to raw inter-arrival times. This 7/8 weighting provides low-pass filtering that prevents single fast packets from triggering false burst detection, enabling stable working-set expansion decisions. Gen 8 achieves 275.99 vs Gen 3's 270.98 (+1.9%), with the smoothing contributing to consistent performance across all 8 validation traces. The burst threshold comparison (smoothed_inter_arrival_ns < 5ms) gates a 1.5x working-set expansion (not 2x, which would over-retain pages). This pattern is more robust than raw inter-arrival comparisons and demonstrates that temporal filtering of network metrics yields more stable eviction decisions than instantaneous measurements.

- **Promoted tier (tier 3) with extended protection window independent of session state** (Current Best: Gen 8, Score 275.99): The program creates a top-tier protection category for folios with access_tier == 3 (promoted), protecting them with a 150ms window regardless of whether an active network session exists. This decouples promoted-page protection from session_active gating, allowing truly critical pages to remain cached even during idle periods. Gen 8 achieves 275.99 vs Gen 6's 272.04 (+1.4%), with the promoted tier enabling more nuanced retention decisions. The tier is assigned when effective_access_count >= 5 (after decay), ensuring that only genuinely hot pages receive this extended protection. This creates a three-level hierarchy: (1) promoted tier with unconditional 150ms protection, (2) hot/very_hot pages with session-gated protection, (3) working-set pages with session-gated protection. The key insight is that the most frequently accessed pages should have protection independent of network session state, preventing cache misses on critical data even during idle periods.

- **Aggressive eviction of single-access cold pages with extended age threshold** (Current Best: Gen 8, Score 275.99): The program explicitly targets single-access folios (effective_access_count == 1) that are older than 3x the base recent-access window (150ms), evicting them aggressively. This targets scan workloads (YCSB-D, uniform) where pages are accessed once and never again, preventing them from monopolizing cache. Gen 8 achieves 146,870.89 ops/sec on YCSB-D (update-heavy) with 94µs p99 latency, demonstrating that aggressive cold-page eviction enables high throughput on workloads with limited working sets. The 3x multiplier (150ms vs 50ms base) ensures that pages accessed during initial scans are evicted quickly, freeing cache for hot pages. This pattern complements the multi-tier protection logic by creating asymmetric eviction pressure: hot pages are protected aggressively, while cold pages are evicted aggressively, maximizing cache utilization for the active working set.

## Ineffective Approaches

- **Static decay windows without network-state adaptation** (Gen 3, Score 270.98 vs Gen 8, Score 275.99): Gen 3 uses a fixed ACCESS_DECAY_HALF_LIFE_NS (500ms) regardless of network conditions, whereas Gen 8 adapts the decay window to congestion (250ms) and bursts (750ms). Gen 8's adaptive approach improves the combined score by 1.9%, demonstrating that static decay windows are suboptimal. During congestion, a 500ms window retains stale pages too long, causing cache misses on current working-set pages; during bursts, a 500ms window evicts hot pages too aggressively, causing unnecessary misses. The lesson is that decay mechanisms must be coupled to network state to achieve optimal cache utilization across diverse traffic patterns.

- **Raw inter-arrival time for burst detection without smoothing** (Gen 3 vs Gen 8): Gen 3 uses smoothed_inter_arrival_ns but Gen 8 refines the smoothing factor and burst threshold, achieving 275.99 vs 270.98 (+1.9%). The key difference is that Gen 8's 7/8 exponential smoothing (BURST_SMOOTH_SHIFT = 3) provides more stable filtering than simpler approaches. Programs that react to instantaneous inter-arrival times (without smoothing) would suffer from false-positive burst detection on single fast packets, causing unnecessary working-set expansion and cache pollution. The lesson is that network metrics must be temporally filtered to avoid reactive oscillations in eviction policy.

- **Overly conservative protection windows on read-heavy workloads** (Gen 0, Score 267.06 vs Gen 8, Score 275.99): Gen 0 uses fixed RECENT_ACCESS_NS (100ms) and WORKING_SET_NS (1s) without adaptive shrinking during congestion. Gen 8 shrinks RECENT_ACCESS_NS to 25ms during congestion/high-RTT, enabling more aggressive eviction of pages that are not in the current hot set. Gen 8 achieves 626.70 ops/sec on YCSB-A (read-heavy) vs Gen 0's 622.53 (+0.7%), with the adaptive shrinking preventing unnecessary cache retention. The lesson is that conservative static windows over-protect pages at the cost of eviction pressure, whereas adaptive windows that tighten during congestion enable better cache utilization.

- **Lack of tier-based protection hierarchy** (Gen 0-1 vs Gen 8): Early programs (Gen 0, Gen 1) use binary hot/cold classification without a promoted tier, whereas Gen 8 introduces tier 3 (promoted) with unconditional 150ms protection. Gen 8 achieves 275.99 vs Gen 0's 267.06 (+3.3%), demonstrating that multi-tier hierarchies enable more nuanced retention decisions. The promoted tier allows the most frequently accessed pages to receive extended protection independent of session state, preventing cache misses on critical data. Programs without this tier cannot distinguish between "hot" (access_count >= 3) and "very hot" (access_count >= 5), leading to suboptimal protection decisions.

This pattern is more robust than raw inter-arrival comparisons and contributes to consistent performance across all 8 validation traces. The key insight is that network metrics should be temporally filtered using exponential smoothing to avoid reactive oscillations in eviction policy.

- **Tier assignment based on decayed access count** (Current Best: Gen 8): The folio_accessed callback updates access_tier based on effective_access_count (after decay): tier 3 if >= 5, tier 2 if >= 3, tier 1 if >= 2, tier 0 otherwise. # META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

# Actionable Recommendations for Future Program Mutations

1. **Implement RTT-relative burst detection with adaptive thresholds** — The current BURST_THRESHOLD_US (5ms) is absolute and doesn't scale with network latency; on high-RTT networks (net_srtt_us > 50ms), 5ms inter-arrivals are not actually bursts. Compute a dynamic burst threshold as `max(5ms, net_srtt_us / 4)` in `get_adaptive_decay_window_ns()` so that burst detection scales with observed RTT, preventing false-positive burst detection on high-latency networks (which over-expands working sets and hurts read-heavy workload performance like YCSB-A at 626.70 ops/sec). This directly addresses the weak read-heavy p99 latencies (207-279ms range) by tightening protection windows on high-RTT connections.

2. **Add congestion-aware working-set window shrinking during loss events** — Currently, `get_adaptive_working_set_ns()` only expands during bursts but doesn't shrink during congestion; when `net_lost > 0` or `net_retrans_out > 0`, reduce WORKING_SET_NS_BASE from 500ms to 250ms to focus eviction on the most-recently-accessed pages and reduce cache pollution from older working-set members. This complements the existing congestion-aware RECENT_ACCESS_NS shrinking (already proven effective in Gen 8) and follows the pattern that congestion should trigger protective mode, potentially improving YCSB-D performance further (currently 146,870.89 ops/sec) while maintaining read-heavy workload stability.

3. **Introduce access-count-weighted recency scoring to break ties in eviction decisions** — Currently, the eviction callback uses binary protection rules (protect if hot AND recently_used, else evict), which doesn't differentiate between a folio with effective_access_count=3 and one with effective_access_count=10 when both are equally recent. Implement a continuous scoring function `score = effective_accesses * 10 + (1 - (now - last_access_ts) / recent_access_ns) * 100` and evict only folios with score < threshold (e.g., 50), creating a ranking rather than binary decisions that allows more nuanced eviction choices at tier boundaries. This could improve the harmonic mean score by 0.5–1% by better handling boundary cases between tiers without requiring algorithmic overhauls.

4. **Refine promoted tier assignment to use multi-level decay windows instead of fixed thresholds** — The current promoted tier (tier 3) uses a fixed PROMOTED_THRESHOLD (5) and PROMOTED_PROTECTION_NS (150ms), but these don't adapt to network state; instead, compute promoted-tier protection windows dynamically as `PROMOTED_PROTECTION_NS * (1 + (net_srtt_us / HIGH_RTT_THRESHOLD_US))` so that high-RTT networks extend protection for promoted pages (since cache misses are more expensive), while low-latency networks tighten it. This extends the successful multi-tier hierarchy pattern (which contributed 1.4% improvement from Gen 6 to Gen 8) by making the top tier network-aware, potentially improving consistency across diverse network conditions.

5. **Implement two-pass eviction with promotion list for very-hot folios during congestion** — Currently, all folios are evaluated in a single pass; instead, use `bpf_cache_ext_list_iterate_extended()` with a continue_list to implement a two-pass strategy where folios with `effective_access_count >= 7` (very-hot) are moved to a promotion list during congestion (net_lost > 0), ensuring they are re-evaluated last and protected with extended windows. This mirrors the successful two-tier protection hierarchy already proven in Gen 8 and creates an explicit "safe zone" for critical pages during network stress, potentially improving YCSB-D p99 latency (currently 94µs) by preventing eviction of hot pages during loss events.
