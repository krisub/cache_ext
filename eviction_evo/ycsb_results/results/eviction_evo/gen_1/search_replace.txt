Looking at the performance metrics, I can see several issues:

1. **ycsb_e (scan-heavy)** has very low throughput (118.46) - the policy is likely evicting pages needed for sequential scans
2. **ycsb_d (temporal locality)** has extremely high throughput (142926.25) but this seems like an outlier - likely a measurement artifact
3. **uniform workloads** have low throughput (132.53, 265.36) - the policy doesn't handle uniform/random access patterns well
4. **Read-heavy workloads (b, c)** have moderate throughput but could be better

The current policy uses a simple recency-based approach with a single list. The main problems are:

1. **No scan detection**: Sequential scans (ycsb_e) are treated as random accesses, causing unnecessary evictions
2. **No adaptive thresholds**: The fixed 100ms RECENT_ACCESS_NS window doesn't adapt to network conditions
3. **Ignoring network congestion signals**: We have access to `net_lost`, `net_retrans_out`, `net_mdev_us` but don't use them to adjust protection
4. **No frequency-based protection**: Folios with high access counts should be protected more aggressively

My strategy:
1. **Add network-aware adaptive thresholds** - when network is congested (high loss/retrans), tighten protection to avoid costly cache misses
2. **Implement burst detection** - use inter-arrival times to detect request bursts and protect working set during bursts
3. **Add scan detection** - track sequential access patterns and protect sequential pages
4. **Improve hot folio protection** - use access frequency more aggressively in eviction decisions

static __always_inline u64 get_adaptive_recent_access_ns(void)
{

    bool high_rtt = (net_srtt_us > HIGH_RTT_THRESHOLD_US);

static __always_inline u64 get_adaptive_working_set_ns(void)
{
    u64 threshold = WORKING_SET_NS_BASE;

    // Detect burst: if inter-arrival time is small, we're in a burst
    u64 inter_arrival = (last_packet_ts > net_prev_packet_ts) ?
                        (last_packet_ts - net_prev_packet_ts) : 0;

    if (inter_arrival_us > 0 && inter_arrival_us < BURST_THRESHOLD_US) {
