<DESCRIPTION>
The current program applies recency as an additive bonus after network-aware protection is applied. This means recency and network factors don't compound properly - a recently-accessed folio with moderate access_count doesn't get the full benefit of protection during network congestion.

The best-performing program (Generation 39, score 2184.76) applied recency as a multiplicative factor to access_count BEFORE network protection, allowing these factors to compound. This better distinguishes recently-active working-set folios from old cold folios with similar historical access counts.

Change from:
```c
s64 base_score = (s64)meta->access_count;
s64 score = (base_score * network_factor) / 100;
score += recency_bonus;  // Additive, doesn't compound
```

To:
```c
s64 base_score = ((s64)meta->access_count * (100 + recency_factor)) / 100;
s64 score = (base_score * network_factor) / 100;  // Compounds with recency
```

This also simplifies the recency calculation by using straightforward linear decay over time windows instead of the complex exponential approximation formula. The linear approach performed significantly better (2184.76 vs 1916.59) and is more predictable.
</DESCRIPTION>
