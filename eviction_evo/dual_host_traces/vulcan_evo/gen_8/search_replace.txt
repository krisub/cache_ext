<DESCRIPTION>
The recommendation suggests integrating packets-in-flight (PACKETS_OUT EWMA) as a congestion signal by comparing it against the congestion window (SND_CWND EWMA). Currently, the program enables PACKETS_OUT tracking but doesn't use it in the scoring function to detect when the network is congested (packets_out >> cwnd).

When `packets_out_ewma > cwnd_ewma * 0.8` (indicating high utilization of the congestion window), we're in a congested state where every cache miss is particularly expensive. In this scenario, we should apply an additional 1.1x boost to the network_factor to protect the working set more aggressively.

This requires:
1. Enabling GF_SND_CWND with EWMA listener to get smoothed cwnd values
2. Adding congestion ratio detection logic in bpf_score_fn
3. Applying secondary protection boost when high congestion is detected

This complements the existing RTT trend detection and provides a direct signal of TCP stack pressure.
