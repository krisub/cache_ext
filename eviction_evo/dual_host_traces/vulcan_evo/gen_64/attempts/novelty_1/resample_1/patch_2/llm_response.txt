<DESCRIPTION>
Implement time-decay for the loss signal protection to prevent sustained over-protection from stale loss events while maintaining responsiveness to transient congestion.

The current implementation uses RollingWindow for loss detection with static boost values (115%, 108%, 103%) for different window positions. This doesn't provide smooth time-based decay and can cause over-protection when loss events age out.

This change:
1. Adds a static global `last_loss_observed_ts` within the EVOLVE-BLOCK to track when loss was last detected
2. Switches back to MINMAX listener for GF_LOST (simpler, proven effective in best-performing generation)
3. Implements linear time-decay of the loss boost factor: starts at 115% when loss is detected, decays to 100% (no boost) over 150ms
4. The decay rate is 1% per 10ms, ensuring responsive protection during active congestion while preventing sustained over-protection from stale signals
5. Also refines recency bonus calculation for better temporal granularity

The scoring function updates `last_loss_observed_ts` whenever it observes loss, and calculates the boost based on time elapsed since then. This provides natural, continuous decay that adapts faster to changing network conditions.

Formula: `loss_boost = 115 - (time_since_loss_ns / 10000000)` clamped to [100, 115]
- At 0ms: 115% (full protection)
- At 100ms: ~105% (moderate protection)  
- At 150ms+: 100% (no boost, fully recovered)
