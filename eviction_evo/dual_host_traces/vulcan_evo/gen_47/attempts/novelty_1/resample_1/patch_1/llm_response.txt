<DESCRIPTION>
The current program applies a fixed -100 penalty to all cold folios (interval_ewma > 5 seconds), which over-penalizes long-lived but valuable pages like LevelDB index structures that are accessed infrequently but remain critical to performance. This modification scales the cold folio penalty by historical access count to distinguish between truly unused pages (low access_count) and long-lived valuable structures (high access_count with infrequent but consistent access).

The scaling works as follows:
- access_count < 5: Full -100 penalty (truly cold/unused pages)
- access_count < 20: Reduced -50 penalty (moderately accessed over lifetime)
- access_count >= 20: Minimal -25 penalty (frequently accessed historically, just not recently)

This asymmetric penalty structure preserves the existing +100 hot folio bonus while preventing excessive eviction of long-lived metadata structures. The thresholds are calibrated based on typical LevelDB access patterns where index blocks accumulate moderate access counts over time but have naturally high inter-access intervals.

This change addresses the observed higher variance in dual_small_vs_large (std: 217.25 in best program) by providing more stable protection for persistent working set elements while still preferring genuinely cold pages as victims.
