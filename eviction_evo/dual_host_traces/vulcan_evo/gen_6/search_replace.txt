<DESCRIPTION>
The current implementation uses fixed time-based thresholds for heat classification:
- Hot folios: interval_ewma < 1 second
- Cold folios: interval_ewma > 10 seconds
- Recency window: 5 seconds

These hard-coded values don't adapt to different workload patterns. The recommendation suggests using data-driven, adaptive thresholds based on observed inter-access intervals.

The key insight is that the global inter-arrival EWMA (smoothed packet arrival time) provides a workload-specific baseline. By deriving per-folio heat thresholds as multiples of this global baseline, we make the policy adaptive:

- If packets arrive frequently (low inter-arrival), then:
  - Hot = folio accessed more frequently than most packets (interval_ewma < 2× inter_arrival_ewma)
  - Cold = folio accessed much less frequently (interval_ewma > 10× inter_arrival_ewma)
- If packets arrive sparsely (high inter-arrival), then:
  - Hot thresholds scale up proportionally
  - Cold thresholds scale up proportionally

This way, under burst traffic the working set is tighter; under sparse traffic the definitions relax.

Additionally, reduce the fixed recency window from 5s to 3s to be more selective during eviction pressure.

Changes:
1. Enable GF_INTER_ARRIVAL listener with EWMA to track global packet inter-arrival patterns
2. In bpf_score_fn, compute dynamic hot/cold thresholds as multiples of inter_arrival_ewma
3. Adjust recency window to 3 seconds for tighter adaptation
</DESCRIPTION>
