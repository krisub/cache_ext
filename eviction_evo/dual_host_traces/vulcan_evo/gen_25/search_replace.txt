<DESCRIPTION>
The current program uses fixed RTT thresholds (5ms and 10ms) for protection scaling, which may be suboptimal across diverse network conditions. The recommendation is to implement adaptive RTT baseline tracking with dynamic threshold scaling, entirely within the EVOLVE-BLOCK.

**Key insight**: Track a long-term EWMA of RTT with very low alpha (50) as a workload-specific "baseline" using a static variable, then scale protection dynamically based on deviation from baseline. This approach:

1. **Adapts to workload characteristics**: Each workload establishes its own normal RTT baseline
2. **Relative scaling is more robust**: Protection scales based on stress deviation from normal
3. **Within EVOLVE-BLOCK**: Uses only static variables for baseline tracking, avoiding external map overhead

Instead of hard-coded thresholds (>5ms → 1.25x, >10ms → 1.5x), protection becomes: `100 + (current_rtt - baseline_rtt) * multiplier`, providing 25% extra protection when 2ms above baseline, 50% protection when 4ms above, etc. This normalizes for workload-specific network conditions without manual tuning.
</DESCRIPTION>
