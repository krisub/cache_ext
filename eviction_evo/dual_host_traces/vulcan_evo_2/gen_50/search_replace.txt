<DESCRIPTION>
The current program shows a regression (5223.20) compared to the fifth-best program (5667.51) due to the sequential vs random classification logic that uses inter-arrival patterns. This classification is too aggressive and misidentifies access patterns.

Instead, I'm implementing a more reliable congestion detection mechanism that combines two signals:
1. CWND collapse: When the EWMA of congestion window falls significantly below its historical minimum (indicating sustained window reduction, not just a transient dip)
2. Loss persistence: When packet losses are observed (vulcan_get_max(GF_LOST) > 0)

This dual-metric approach distinguishes between:
- Transient congestion: CWND temporarily low but recovering quickly
- Sustained congestion: CWND stuck below historical minimum while losses persist

The implementation:
1. Enable MINMAX listener for GF_SND_CWND (currently only has EWMA)
2. Add detection logic: when cwnd_ewma < cwnd_min * 1.3 AND lost_max > 0
3. Stack an additional +1000 bonus with existing loss-triggered bonuses (not replacing them)
4. Use conservative 1.3x ratio threshold to avoid false positives

This complements the existing jitter-aware protection and provides more reliable working-set expansion identification during genuine sustained congestion periods.
