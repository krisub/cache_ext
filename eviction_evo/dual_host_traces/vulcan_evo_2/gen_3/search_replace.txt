<DESCRIPTION>
The current policy shows a regression in write-heavy workloads (ycsb_a_d drops from 4963 to 4384), suggesting it's too conservative. The main issues are:

1. **Unrealistic RTT thresholds**: 50ms is very high for typical LAN setups (usually <10ms). We need more realistic thresholds.

2. **Unused cwnd metric**: We enable EWMA for congestion window but don't use it. Low cwnd directly indicates network congestion.

3. **Over-protection of recency**: The 5s/30s recency windows with large bonuses (+3000/+1000) cause the policy to favor recently-touched pages too much in write-heavy workloads, where many pages get touched but only some are truly hot.

4. **Coarse interval thresholds**: The 100ms/1s thresholds for per-folio heat don't distinguish hot folios well enough.

This change refines the scoring function to:
- Use realistic RTT thresholds (15ms as "high" vs 50ms)
- Scale RTT bonus proportionally instead of fixed tiers
- Add cwnd-based congestion detection (cwnd < 10 segments = congested)
- Tighten per-folio interval heat detection (50ms/500ms/2s tiers)
- Reduce recency bonuses (2s/10s windows with smaller bonuses) to better balance with frequency

This should reduce over-protection in write-heavy workloads while maintaining network-adaptive behavior.
</DESCRIPTION>
