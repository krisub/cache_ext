<DESCRIPTION>
The current policy detects congestion via packet loss (GF_LOST) but doesn't distinguish between transient loss events and sustained congestion window collapse. TCP enters congestion avoidance when CWND drops below SSTHRESH, indicating prolonged network degradation rather than isolated packet drops.

This edit introduces a secondary congestion signal by:
1. Enabling GF_SND_SSTHRESH MINMAX listener to track the slow-start threshold
2. Detecting when CWND (EWMA) < SSTHRESH (minimum observed) * 1.5, indicating the connection is in congestion avoidance phase
3. When both loss AND cwnd collapse are present, applying an additional +2000 bonus specifically to the recency-based protection (stacking multiplicatively)

This amplifies working-set protection only during sustained congestion (not transient loss), targeting recently-accessed folios that are most likely to be re-requested soon. The multiplicative stacking creates stronger protection than generation 9's unconditional +1500 bonus, while being more selective about when to apply it.

Reasoning: During sustained congestion (cwnd below ssthresh), cache misses are extremely expensive due to slow network recovery. By amplifying recency bonuses only in this specific scenario, we protect the working set more aggressively when it matters most, potentially improving performance on workloads experiencing variable congestion patterns.
</DESCRIPTION>
