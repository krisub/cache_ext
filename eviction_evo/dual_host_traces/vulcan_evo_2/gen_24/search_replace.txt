cwnd_aware_loss_amplification
</NAME>

<DESCRIPTION>
Implement CWND-aware loss amplification with sustained congestion detection. The current policy detects packet loss via `vulcan_get_max(GF_LOST)` but treats all loss events equally. This change distinguishes between transient packet loss (where CWND recovers quickly) and sustained congestion (where CWND remains depressed).

The modification:
1. Enables MINMAX listener for GF_SND_CWND to track minimum congestion window
2. Adds sustained congestion detection: when `cwnd_ewma < cwnd_min * 1.3`, the connection is stuck in slow recovery rather than experiencing brief loss
3. Amplifies loss-triggered recency bonuses by 30% during sustained congestion (e.g., +4500 becomes +5850)

This refinement helps protect the working set more aggressively when the network is under sustained stress (where re-fetching evicted pages is most expensive) while avoiding over-protection during normal congestion avoidance transitions. This should improve performance on workloads like YCSB A/B/D (currently 4126-5384 ops/sec) where sustained congestion correlates with higher cache miss penalties.
</DESCRIPTION>
