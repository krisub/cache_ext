# Program Evaluation Analysis

## Successful Algorithmic Patterns

- **Congestion-aware recency bonuses with loss-triggered amplification achieve +0.6% improvement over baseline multi-layered scoring**: The current best program (Generation 13, score 5099.34) extends the proven multi-layered approach from Generation 8 (4743.22) by introducing loss-triggered recency amplification: during packet loss detection (`if (lost_max > 0)`), recency bonuses increase from +3000 to +4500 for folios <5 seconds old, and from +1000 to +1500 for folios <30 seconds old, with an additional +500 bonus for folios <60 seconds old. This loss-aware extension adds 356.12 points (+7.5% improvement) over Generation 8's score, demonstrating that network stress signals (packet loss) can be leveraged to extend working-set protection windows during congestion. The key insight is that packet loss is a strong indicator of sustained network degradation, and during such periods, the working set should be protected more aggressively by amplifying recency bonuses rather than relying solely on access frequency. This approach outperforms Generation 9's CWND collapse detection (4566.55, -532.79 points vs. Generation 13), suggesting that loss-triggered recency amplification is a more effective congestion signal than CWND ratio analysis.

- **Per-folio EWMA alpha tuning (200 for interval tracking) combined with selective global feature EWMA alphas (275 for RTT, 175 for CWND, 60 for inter-arrival) enables multi-timescale network awareness**: Generation 13 achieves 5099.34 by carefully tuning EWMA smoothing constants across different network features and per-folio intervals. The RTT EWMA uses alpha=275 (higher smoothing, slower response to transient spikes), CWND uses alpha=175 (moderate smoothing), inter-arrival uses alpha=60 (aggressive smoothing for rapid detection of packet arrival pattern changes), and per-folio interval tracking uses alpha=200. This multi-timescale approach recognizes that different network metrics have different natural timescales: RTT changes slowly (milliseconds to seconds), CWND responds to congestion events (seconds), inter-packet arrival times change rapidly (microseconds to milliseconds), and per-folio access intervals vary by workload (milliseconds to seconds). By tuning each EWMA alpha independently, Generation 13 achieves better responsiveness to network changes without over-reacting to noise. This pattern outperforms Generation 8's fixed alpha=200 for all features (4743.22, -356.12 points), demonstrating that per-feature EWMA tuning adds meaningful signal for network-aware cache eviction.

- **Extended recency protection window (60-second tier) during congestion captures sustained working-set retention without over-protecting**: Generation 13 introduces a third recency tier (`if (age < 60000000000)` with +500 bonus during congestion) beyond Generation 8's two-tier approach (5-second and 30-second tiers). This extended window recognizes that during sustained network congestion (indicated by persistent packet loss), the working set may expand beyond the 30-second window as applications adapt to higher latency by batching requests or increasing concurrency. The +500 bonus is conservative (much smaller than the +4500 and +1500 bonuses for shorter windows), ensuring that very old folios are not over-protected, but recently-accessed folios within the 60-second window receive modest protection during stress. This three-tier recency approach achieved 5099.34 vs. Generation 8's two-tier approach (4743.22, +356.12 points), suggesting that the extended window captures additional working-set retention benefit during congestion without introducing thrashing. The pattern demonstrates that recency protection should scale with network stress: during normal conditions, focus on 5-30 second windows; during congestion, extend to 60 seconds with conservative bonuses.

- **Selective listener enablement (3 global features + per-folio interval tracking) with early-exit guard maintains zero-overhead baseline while achieving +20.9% improvement over pure LFU**: Generation 13 enables only three global feature listeners (GF_SRTT_US with EWMA, GF_SND_CWND with EWMA, GF_LOST with MINMAX) plus per-folio interval tracking (MINMAX + EWMA), leaving 13 of 16 global features disabled. The kprobe includes an early-exit check that returns immediately if no listeners are enabled, ensuring baseline compatibility. This selective approach achieved 5099.34 vs. the baseline (4217.68, +881.66 points or +20.9% improvement), demonstrating that focused network monitoring on the most impactful metrics (RTT, congestion window, packet loss) is more effective than comprehensive monitoring. The pattern contrasts with the failed programs (Generations 2-4) that attempted to use more complex feature sets and violated BPF constraints, and with Generation 9 (4566.55) which added CWND collapse detection without improving performance. The insight is that selective listener enablement reduces kprobe overhead, simplifies the scoring function, and focuses the policy on the most actionable network signals.

## Ineffective Approaches

- **CWND collapse detection as a primary congestion signal underperforms loss-triggered recency amplification by 532.79 points**: Generation 9 (score 4566.55) attempted to add explicit CWND collapse detection to the scoring function, implementing logic to detect when CWND falls below slow-start threshold or near zero. While the feedback noted that "CWND collapse detection is a valid protection mechanism," the actual performance (4566.55) is 176.67 points lower than Generation 8 (4743.22) and 532.79 points lower than Generation 13 (5099.34). This regression suggests that CWND collapse is either too transient a signal (CWND recovers quickly after congestion events) or requires more sophisticated threshold tuning to avoid over-protecting during normal congestion avoidance phase transitions. The pattern demonstrates that while CWND is a valid network metric, using it as a primary congestion indicator is less effective than using packet loss (which persists across multiple RTT periods) or RTT elevation (which is more stable). Generation 13's approach of using loss detection to amplify recency bonuses outperforms Generation 9's CWND collapse approach, suggesting that loss is a more reliable congestion signal for cache eviction policy.

- **Aggressive RTT ratio calculations and division-by-variable operations violate BPF compiler constraints and cause complete compilation failure**: Generations 2, 3, and 4 all attempted sophisticated RTT-based scoring using signed division operations (e.g., `(rtt_ewma * 100) / (rtt_min + 1)`, `(rtt_ewma - 15000) / 30000`, `(packets_out * 100) / cwnd`), resulting in score 0.00 due to BPF compiler rejection. The feedback explicitly states: "BPF compiler (clang-14) rejects signed integer division... BPF requires unsigned division; the expression must be rewritten using unsigned types or bit-shifts." This pattern demonstrates that while ratio-based scoring is theoretically sound for normalizing RTT relative to baseline, the BPF backend's lack of `sdiv` instruction support makes such approaches infeasible. The successful programs (Generations 6-13) avoid this entirely by using simple addition-based bonuses with division by constants (compiled to bit-shifts), proving that conservative additive scoring is both safer and sufficient. The pattern is critical: any attempt to use division-by-variable or complex arithmetic in BPF scoring functions will fail compilation, regardless of the algorithmic soundness of the approach.

- **Nested conditional logic with multiple arithmetic branches and complex pressure calculations exceed BPF verifier path explosion limits**: The failed programs (Generations 2-4) attempted to implement sophisticated heuristics with multiple division operations, conditional branches for pressure calculations, and interdependent ratio-based multipliers. The feedback for Generation 4 notes: "the design is sound (network-aware protection logic, per-folio heat tracking, LevelDB index block preservation), but the implementation violates BPF backend constraints and cannot be validated functionally." This indicates that even theoretically correct designs fail if they exceed the verifier's instruction count or path explosion limits. The successful programs maintain scoring functions under ~50 lines of straightforward C with simple if-then-add patterns, avoiding nested conditionals and complex arithmetic. Generation 13's scoring function, for example, uses a flat sequence of independent protection checks (RTT tiers, loss detection, heat detection, variance detection, recency with loss amplification) rather than nested conditionals or interdependent calculations, keeping the verifier's path count manageable. The pattern demonstrates that BPF verifier constraints require flat, linear scoring logic rather than complex branching structures.

- **Enabling all 16 global feature listeners without selective tuning adds overhead without proportional benefit and destabilizes scoring precision**: While not explicitly tested in the provided summaries, the pattern across successful programs shows that selective listener enablement outperforms comprehensive monitoring. Generation 13 enables only 3 of 16 global features (GF_SRTT_US, GF_SND_CWND, GF_LOST) while leaving 13 disabled, achieving 5099.34. The early-exit kprobe check ensures that when no listeners are enabled, the kprobe returns immediately with zero overhead. Enabling unnecessary listeners increases kprobe execution time, map update frequency, and scoring function complexity without proportional benefit. The principle is evident in the feedback for earlier programs: "The kprobe overhead is mitigated by an early-exit check that disables monitoring when no listeners are enabled, matching baseline performance." Comprehensive monitoring approaches would increase the number of map lookups in the scoring function (from 3 to 16), potentially causing instruction count violations or verifier rejection. The pattern demonstrates that selective feature tuning is more effective than exhaustive monitoring for both performance and correctness.

## Implementation Insights

- **Loss-triggered recency amplification pattern enables dynamic working-set protection scaling without introducing new network metrics**: Generation 13's implementation uses a simple conditional pattern: `if (lost_max > 0) { score += 4500; } else { score += 3000; }` for the <5-second recency tier, and similar amplification for the 30-second and 60-second tiers. This pattern reuses the existing packet loss detection (GF_LOST with MINMAX listener) to modulate recency bonuses, avoiding the need for new network metrics or complex calculations. The implementation is elegant: it recognizes that packet loss is a strong indicator of sustained congestion, and during such periods, the working set should be protected more aggressively by amplifying recency bonuses. The pattern requires only two additional conditional branches per recency tier (checking `if (lost_max > 0)`), adding minimal instruction count overhead while providing substantial performance benefit (+356.12 points vs. Generation 8). This approach is more effective than Generation 9's CWND collapse detection because loss is a more persistent signal (packet loss persists across multiple RTT periods), whereas CWND recovers quickly after congestion events. The implementation demonstrates that effective network-aware cache eviction can be achieved through simple conditional amplification of existing scoring components rather than introducing new metrics or complex calculations.

- **Multi-timescale EWMA alpha tuning (275 for RTT, 175 for CWND, 60 for inter-arrival, 200 for per-folio intervals) enables independent responsiveness to different network phenomena**: Generation 13's configuration uses different EWMA alphas for different features, recognizing that each network metric has a different natural timescale and noise characteristics. RTT uses alpha=275 (higher smoothing, slower response) because RTT changes slowly and is noisy; CWND uses alpha=175 (moderate smoothing) because CWND responds to congestion events on a seconds timescale; inter-arrival uses alpha=60 (aggressive smoothing) because inter-packet arrival times change rapidly and need quick detection; per-folio intervals use alpha=200 (moderate smoothing) because access intervals vary by workload. The EWMA update formula is `new_value = (old_value * (1000 - alpha) + new_sample * alpha) / 1000`, so higher alpha means faster response to new samples. By tuning each alpha independently, Generation 13 achieves better responsiveness to network changes without over-reacting to noise. This pattern outperforms Generation 8's fixed alpha=200 for all features (4743.22, -356.12 points), demonstrating that per-feature EWMA tuning adds meaningful signal. The implementation is straightforward: each feature's config struct specifies its own `.ewma_alpha` value, and the vulcan framework applies the appropriate alpha during updates. The pattern demonstrates that effective network-aware scoring requires understanding the timescale of each metric and tuning smoothing constants accordingly.

- **Three-tier recency protection with loss-triggered amplification captures working-set dynamics across multiple timescales**: Generation 13 implements recency protection with three tiers: <5 seconds (primary working set), <30 seconds (extended working set), and <60 seconds (sustained congestion protection). Each tier has a base bonus and a loss-amplified bonus, creating a dynamic protection strategy that scales with network stress. The implementation uses simple age comparisons (`if (age < 5000000000)`, `else if (age < 30000000000)`, `else if (age < 60000000000)`) followed by conditional amplification based on packet loss. The bonuses are conservative and tiered: +4500/+3000 for <5s, +1500/+1000 for <30s, +500/+0 for <60s, ensuring that very old folios are not over-protected. This three-tier approach achieved 5099.34 vs. Generation 8's two-tier approach (4743.22, +356.12 points), suggesting that the extended 60-second window captures additional working-set retention benefit during congestion. The pattern demonstrates that recency protection should be multi-tiered to capture different working-set dynamics: the primary working set (recently accessed), the extended working set (accessed within 30 seconds), and the sustained-stress working set (accessed within 60 seconds during congestion).
