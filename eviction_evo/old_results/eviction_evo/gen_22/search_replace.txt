<DESCRIPTION>
The current program uses a fixed 2ms jitter threshold to detect network instability, but jitter significance is RTT-dependent. A 2ms jitter on a 10ms RTT connection represents 20% variability (severe), while on a 100ms RTT it's only 2% (negligible). This change implements adaptive jitter threshold scaling based on RTT percentile: scale the 2ms baseline by (RTT/100ms) ratio, clamped to [0.5x-2.0x] range (1ms-4ms absolute). This context-aware pressure detection should reduce false positives during high-latency connections while maintaining sensitivity for low-latency ones, potentially improving combined score by maintaining more aggressive eviction during genuinely stable high-latency periods while protecting the working set during actual congestion.
</DESCRIPTION>

    // Adaptive jitter threshold: scale 2ms baseline by (RTT/100ms), clamped [0.5x, 2.0x]
    // This makes jitter interpretation RTT-dependent: 2ms jitter is severe on 10ms RTT
    // but negligible on 100ms RTT. Prevents false pressure detection on high-latency links.
    u32 jitter_threshold_us = 2000000;  // 2ms baseline
    if (net_srtt_us > 0) {
        // True RTT in microseconds = net_srtt_us / 8 (kernel stores srtt<<3)
        u32 true_rtt_us = net_srtt_us >> 3;
        // Ratio = RTT / 100ms, scaled by 1000 to avoid floating point
        u32 ratio_x1000 = true_rtt_us / 100;  // (true_rtt_us * 1000) / 100000
        // Clamp ratio to [0.5, 2.0] = [500, 2000] in x1000 scale
        if (ratio_x1000 < 500)
            ratio_x1000 = 500;
        else if (ratio_x1000 > 2000)
            ratio_x1000 = 2000;
        // Scale threshold: baseline * ratio
        jitter_threshold_us = (jitter_threshold_us * ratio_x1000) / 1000;
    }
    bool high_jitter = (net_mdev_us > jitter_threshold_us);
