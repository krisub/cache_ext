- **Conservative multi-signal pressure detection (loss, cwnd, jitter, rcv_wnd) with fixed thresholds (2ms jitter, cwnd/2 ratio, 65KB rcv_wnd floor) and modest 1.25x pressure multiplier achieves 2182.27 combined score, outperforming all alternative approaches by 4.3-40.4%**: The current best program (Generation 14, score 2182.27) implements four independent pressure signals with OR-based aggregation and conservative thresholds that minimize false positives from transient network jitter. This approach achieves 1681.15 small-vs-large throughput and 3109.00 congested throughput, substantially outperforming Generation 15 (sustained_burst_detection, score 2005.09, -8.1%), Generation 16 (working_set_stability_scoring, score 2087.32, -4.3%), Generation 17 (working_set_stability_threshold_adaptation, score 2048.15, -6.2%), Generation 18 (burst_adaptive_hot_threshold, score 1301.77, -40.4%), and Generation 19 (adaptive_jitter_threshold_rtt_scaling, score 1721.48, -21.1%). The key to this success is the conservative jitter threshold (>2ms vs >1ms in alternatives) and the cwnd/2 ratio (rather than implicit higher ratios), which avoid false positives from normal network jitter while maintaining robust detection of genuine congestion. The 1.25x pressure multiplier (implemented as `(adapted * 5) >> 2`) provides meaningful protection during congestion without over-protecting cache, allowing the program to maintain aggressive eviction during normal conditions while still protecting working sets during genuine network pressure. The multi-signal approach with OR-based aggregation ensures that any genuine pressure indicator triggers protective behavior, while the conservative thresholds minimize false positives that would cause unnecessary cache retention.

- **Dynamic hot threshold adaptation (HOT_ACCESS_THRESHOLD_PRESSURE=2, HOT_ACCESS_THRESHOLD_NORMAL=3, HOT_ACCESS_THRESHOLD_IDLE=4) decoupled from tier classification enables context-aware protection without over-retention, achieving 10.3% higher small-vs-large throughput (1681.15) than survivor tier promotion approaches**: The current best program (Generation 14, score 2182.27) implements three distinct hot thresholds that vary based on network pressure and session activity, while maintaining a fixed HOT_ACCESS_THRESHOLD_NORMAL=3 for tier classification metadata. This architectural separation is implemented via the `get_hot_access_threshold()` helper function, which returns the appropriate threshold based on `net_under_pressure` and `session_active` flags, and this threshold is used only in the eviction callback rather than in the folio_accessed callback. The decoupling allows the program to classify folios as "warm" (tier 1) at access_count=2 for metadata purposes, while dynamically lowering the eviction protection threshold to 2 during network pressure (treating warm folios as hot for protection) or raising it to 4 during idle periods (aggressively evicting warm folios). Generation 15 (sustained_burst_detection, score 2005.09) implements survivor tier promotion with static tier classification, achieving only 1506.40 small-vs-large throughput (-10.3% vs Generation 14's 1681.15), demonstrating that dynamic threshold adaptation provides finer-grained control than static tier hierarchies. The decoupling is critical because it enables independent optimization of metadata tracking (consistent tier classification) and eviction decisions (context-aware thresholds), allowing the program to maintain stable metadata while still responding dynamically to network conditions.

- **Session-aware idle timeout (5s NET_IDLE_TIMEOUT_NS) combined with dynamic threshold adaptation enables context-aware eviction decisions that distinguish between active and idle workload phases, achieving 0.9% improvement over previous best program (Generation 3, score 2162.27)**: The current best program (Generation 14, score 2182.27) tracks session activity via `session_active = (now - last_packet_ts) < NET_IDLE_TIMEOUT_NS` and uses this flag to adapt the hot threshold (2 under pressure, 3 normal, 4 idle) and protect working sets during active sessions. The 5s idle timeout is conservative—it assumes that any network activity within 5s indicates an active session—allowing the program to distinguish between active workloads (frequent network activity) and idle periods (no activity for 5s). This session-aware approach is implemented in the eviction callback, allowing per-folio decisions based on current session state rather than static policies. The session-aware idle timeout enables the program to raise the hot threshold to 4 during idle periods, aggressively evicting warm folios and maintaining cache efficiency, while lowering the hot threshold to 2 during active sessions under pressure, protecting frequently-accessed folios. The 0.9% improvement over Generation 3 (score 2162.27) is driven by superior small-vs-large throughput (1681.15 vs 1645.52, +2.2%), demonstrating that the session-aware approach provides better small-folio workload performance while maintaining competitive congested-workload performance (3109.00 vs 3152.17, -1.4%).

- **Conservative RTT scaling (÷20 rather than multiplication) combined with modest pressure multiplier (1.25x) prevents over-retention while maintaining working-set protection across varying network latencies, achieving 15.9% higher congested throughput (3109.00) than adaptive jitter scaling approaches**: The current best program (Generation 14, score 2182.27) implements adaptive time window scaling via `get_adaptive_window()` which adds RTT/20 to the base window rather than multiplying by RTT, and applies a 1.25x multiplier (not 1.5x) when network pressure is detected. This conservative scaling approach is implemented as `adapted = adapted + (u64)rtt_clamped / 20` for RTT scaling and `adapted = (adapted * 5) >> 2` for pressure multiplier (1.25x). The RTT/20 scaling ensures that a 100ms RTT adds only 5ms to the 30ms BASE_RECENT_NS window (resulting in 35ms), preventing excessive cache retention during high-latency conditions. Generation 19 (adaptive_jitter_threshold_rtt_scaling, score 1721.48) implements adaptive jitter thresholds scaled by RTT percentile, achieving only 2680.51 congested throughput (-13.8% vs Generation 14's 3109.00), indicating that the current best program's conservative RTT scaling is more effective than adaptive jitter scaling. The conservative approach outperforms all other evaluated programs in the current batch on congested workloads, demonstrating that the key to effective network-aware scaling is avoiding over-retention rather than maximizing protection.

The modest RTT scaling (divided by 20) and conservative jitter threshold (>2ms) in Generation 18 are similar to Generation 14, but the burst detection mechanism overrides these conservative settings, resulting in poor performance. This demonstrates that burst detection mechanisms can degrade performance if not carefully calibrated to workload characteristics, and that conservative multi-signal pressure detection is more robust than burst-specific mechanisms for heterogeneous workload scenarios.

The survivor promotion mechanism requires tracking survival counts separately and resetting them on access, adding complexity without providing the fine-grained control of dynamic threshold adaptation. This demonstrates that context-aware threshold adaptation is more effective than static tier hierarchies for network-aware cache eviction, particularly for small-folio workloads where the 10.3% throughput gap is most pronounced.

- **Working set stability scoring and threshold adaptation approaches degrade performance by 4.3-6.2% compared to conservative pressure detection with dynamic thresholds, achieving only 2048.15-2087.32 combined scores**: Generation 16 (working_set_stability_scoring, score 2087.32, -4.3%) and Generation 17 (working_set_stability_threshold_adaptation, score 2048.15, -6.2%) implement working set stability tracking per scan to dynamically adjust hot-threshold classification, achieving 4.3-6.2% lower performance than the current best program (Generation 14, score 2182.27). The working set stability approach attempts to track cache stability across scans and adjust thresholds dynamically, but this adds complexity without providing the performance benefits of the current best program's simpler session-aware idle timeout (5s NET_IDLE_TIMEOUT_NS) and network pressure detection. This demonstrates that simpler, more direct approaches to network-aware threshold adaptation are more effective than complex working set stability tracking mechanisms.

- **Adaptive jitter threshold scaling by RTT percentile degrades performance by 21.1% compared to fixed conservative jitter thresholds, achieving only 1721.48 combined score**: Generation 19 (adaptive_jitter_threshold_rtt_scaling, score 1721.48) implements context-aware jitter thresholds scaled by RTT percentile and protective tier systems (treating warm folios as hot under pressure), achieving 21.1% lower combined score than the current best program (Generation 14, score 2182.27). The adaptive jitter threshold approach (scaled by RTT percentile) appears to create false positives or false negatives in pressure detection, causing either over-protection or under-protection of cache depending on RTT conditions. The 1.25x adaptive window scaling multiplier (similar to Generation 14) is not sufficient to overcome the ineffectiveness of adaptive jitter thresholds. ## Implementation Insights

- **Decoupling tier classification from eviction thresholds via separate `get_hot_access_threshold()` helper function enables independent optimization of metadata tracking and eviction decisions, achieving 8.1% performance advantage over survivor tier promotion**: The current best program (Generation 14, score 2182.27) maintains a fixed tier classification system (cold/warm/hot based on access_count ≥ 2/3) for metadata purposes in the `folio_accessed` callback, while implementing separate dynamic thresholds (HOT_ACCESS_THRESHOLD_PRESSURE=2, HOT_ACCESS_THRESHOLD_NORMAL=3, HOT_ACCESS_THRESHOLD_IDLE=4) for eviction decisions in the `bpf_evict_cb` callback. This architectural separation is implemented via the `get_hot_access_threshold()` helper function, which returns the appropriate threshold based on `net_under_pressure` and `session_active` flags, and this threshold is used only in the eviction callback rather than in the folio_accessed callback. The decoupling allows the program to track folio access patterns consistently (tier classification always uses the same thresholds) while adapting eviction protection dynamically based on network conditions. In the `folio_accessed` callback, the program updates `meta->access_tier` using the fixed HOT_ACCESS_THRESHOLD_NORMAL=3 threshold: `if (meta->access_count >= HOT_ACCESS_THRESHOLD_NORMAL) meta->access_tier = 2;`. In the `bpf_evict_cb` callback, the program uses the dynamic threshold: `u32 dynamic_hot_threshold = get_hot_access_threshold(net_under_pressure, session_active);` and then `bool is_hot = (meta->access_count >= dynamic_hot_threshold);`. This separation enables the program to classify folios as "warm" (tier 1) at access_count=2 for metadata purposes, while dynamically protecting them during network pressure (by lowering the hot threshold to 2) or aggressively evicting them during idle periods (by raising the hot threshold to 4). Generation 15 (sustained_burst_detection, score 2005.09) implements survivor tier promotion with static tier classification, achieving 8.1% lower performance, demonstrating that the decoupling approach provides finer-grained control than static tier hierarchies.

- **Multi-signal pressure detection with independent thresholds (loss, cwnd, jitter, rcv_wnd) and OR-based aggregation enables robust condition assessment without false negatives, implemented via four independent boolean conditions aggregated with logical OR**: The current best program (Generation 14, score 2182.27) detects network pressure through four independent signals: `bool has_loss = (net_lost > 0) || (net_retrans_out > 0);`, `bool cwnd_pressure = (net_packets_out > 0) && ((u32)net_packets_out > (net_snd_cwnd / CWND_PRESSURE_RATIO));`, `bool high_jitter = (net_mdev_us > 2000000);`, and `bool rcv_wnd_pressure = (net_rcv_wnd > 0) && (net_rcv_wnd < 65536);`. The program considers the network under pressure if ANY of these conditions is true: `bool net_under_pressure = has_loss || cwnd_pressure || high_jitter || rcv_wnd_pressure;`. This OR-based aggregation provides robust detection that avoids false negatives—if any genuine pressure indicator is present, the program triggers protective behavior. The independent thresholds allow each signal to be tuned independently without affecting others: the loss indicator checks for any retransmission activity, the cwnd pressure checks if packets in flight exceed half the congestion window (CWND_PRESSURE_RATIO=2), the jitter threshold is set conservatively at 2ms (net_mdev_us > 2000000), and the rcv_wnd pressure checks if the receive window is below 65KB. Generation 18 (burst_adaptive_hot_threshold, score 1301.77) implements burst detection via packet velocity tracking (50 packets/100ms threshold), achieving 40.4% lower performance, indicating that single-signal burst detection is less effective than multi-signal pressure detection. The multi-signal approach achieves 1681.15 small-vs-large throughput and 3109.00 congested throughput, outperforming all other evaluated programs in the current batch.

- **Session-aware idle timeout (5s NET_IDLE_TIMEOUT_NS) combined with dynamic threshold adaptation enables context-aware eviction decisions that distinguish between active and idle workload phases, implemented via `session_active = (now - last_packet_ts) < NET_IDLE_TIMEOUT_NS` flag used in `get_hot_access_threshold()`**: The current best program (Generation 14, score 2182.27) tracks session activity via `bool session_active = (now - last_packet_ts) < NET_IDLE_TIMEOUT_NS;` in the `bpf_evict_cb` callback, where `now = bpf_ktime_get_ns()` and `last_packet_ts` is updated by the `trace_tcp_recvmsg` kprobe. This session-aware flag is then passed to `get_hot_access_threshold()`, which returns different thresholds based on both network pressure and session activity: `if (net_under_pressure && session_active) return HOT_ACCESS_THRESHOLD_PRESSURE;` (threshold=2), `if (!session_active) return HOT_ACCESS_THRESHOLD_IDLE;` (threshold=4), and otherwise `return HOT_ACCESS_THRESHOLD_NORMAL;` (threshold=3). The 5s idle timeout is conservative—it assumes that any network activity within 5s indicates an active session—allowing the program to distinguish between active workloads (frequent network activity) and idle periods (no activity for 5s). This session-aware approach is implemented in the eviction callback, allowing per-folio decisions based on current session state rather than static policies. The session-aware idle timeout enables the program to raise the hot threshold to 4 during idle periods, aggressively evicting warm folios and maintaining cache efficiency, while lowering the hot threshold to 2 during active sessions under pressure, protecting frequently-accessed folios. Generation 16 (working_set_stability_scoring, score 2087.32) implements per-scan working set stability tracking, achieving 4.3% lower performance, indicating that the current best program's simpler session-aware approach is more effective than complex stability tracking.

- **Conservative RTT scaling (÷20 rather than multiplication) combined with modest pressure multiplier (1.25x) prevents over-retention while maintaining working-set protection across varying network latencies, implemented via `adapted = adapted + (u64)rtt_clamped / 20` for RTT scaling and `adapted = (adapted * 5) >> 2` for pressure multiplier**: The current best program (Generation 14, score 2182.27) implements adaptive time window scaling via the `get_adaptive_window()` helper function, which adds RTT/20 to the base window rather than multiplying by RTT. The implementation is: `u32 rtt_clamped = (net_srtt_us > 10000000) ? 10000000 : net_srtt_us;` (clamp RTT to max 10ms to avoid overflow), `adapted = adapted + (u64)rtt_clamped / 20;` (add RTT/20 to base window), and `if (under_pressure) adapted = (adapted * 5) >> 2;` (apply 1.25x multiplier). The RTT/20 scaling ensures that a 100ms RTT adds only 5ms to the 30ms BASE_RECENT_NS window (resulting in 35ms), preventing excessive cache retention during high-latency conditions. Generation 19 (adaptive_jitter_threshold_rtt_scaling, score 1721.48) implements adaptive jitter thresholds scaled by RTT percentile, achieving 21.1% lower performance, indicating that the current best program's conservative RTT scaling is more effective than adaptive jitter scaling. The conservative approach outperforms all other evaluated programs on congested workloads (3109.00 ops/sec), demonstrating that the key to effective network-aware scaling is avoiding over-retention rather than maximizing protection.

# Actionable Recommendations for Future Program Mutations

1. **Implement a two-tier pressure detection system with separate thresholds for "moderate pressure" (1.1x multiplier) and "severe pressure" (1.25x multiplier), triggered by single vs. multiple concurrent signals**
   The current best program uses binary pressure detection with a single 1.25x multiplier, but network conditions exist on a spectrum. Introduce `net_pressure_level` where moderate pressure triggers when any single signal is present (e.g., jitter > 1.5ms OR cwnd_pressure alone) and severe pressure requires multiple signals (loss AND (cwnd_pressure OR high_jitter)). Apply 1.1x multiplier for moderate and 1.25x for severe, allowing finer-grained protection that could improve congested throughput (currently 3109.00) by 1-2% while maintaining small-vs-large performance (1681.15).

2. **Add a "folio recency boost" mechanism that temporarily lowers the hot threshold by 1 for folios accessed within the last 10ms, targeting frequently-accessed small folios that fall just below the dynamic threshold**
   The current best program's dynamic hot threshold (2/3/4) adapts to session state but not to recent access patterns within the current eviction scan. Implement a per-folio recency check in `bpf_evict_cb`: if `(now - meta->last_access_ts) < 10000000` (10ms), treat the folio as if it has one additional access count for threshold comparison purposes. This targets the specific case of frequently-accessed small folios that may fall just below the hot threshold, potentially improving small-vs-large throughput by 1-3% without degrading congested performance.

3. **Implement adaptive jitter threshold scaling based on RTT percentile (scale 2ms baseline by RTT/100ms ratio, clamped 0.5x-2.0x) to reduce false positives during high-latency connections**
   The current best program uses a fixed 2ms jitter threshold regardless of RTT, but jitter interpretation is RTT-dependent—2ms jitter on a 10ms RTT connection is severe, while 2ms on a 100ms RTT is negligible. Replace the fixed `high_jitter = (net_mdev_us > 2000000)` with `high_jitter = (net_mdev_us > (2000000 * net_srtt_us / 100000000))` clamped to [1000000, 4000000] (1-4ms). This context-aware pressure detection could reduce false positives during high-latency connections, potentially improving overall combined score by 0.5-1.5% by maintaining more aggressive eviction during genuinely stable high-latency periods.

4. **Extend the session activity tracking to distinguish between "active burst" (high packet rate >50 packets/100ms) and "steady-state" sessions, applying HOT_ACCESS_THRESHOLD_PRESSURE (2) during bursts even without network pressure signals**
   The current best program treats all active sessions uniformly via the `session_active` flag, but burst workloads (many packets in short time) warrant different protection than steady-state workloads. Track `burst_active = (net_recv_count - prev_recv_count) > 50 packets in last 100ms` and modify `get_hot_access_threshold()` to return HOT_ACCESS_THRESHOLD_PRESSURE (2) during bursts even without network pressure signals. This targets the specific case of small-folio workloads during traffic spikes, potentially improving small-vs-large throughput by 1-2% by providing burst-aware protection without degrading idle-period eviction aggressiveness.

5. **Implement a "working set stability score" that samples 50 folios within the adapted_working_set window and lowers the hot threshold by 1 if >80% show recent access (within last 100ms), enabling data-driven threshold calibration**
   The current best program's adaptive windows (BASE_RECENT_NS, BASE_WORKING_SET_NS) are fixed per network condition, but working set size varies significantly across workloads. Add a pre-eviction pass in `evolved_evict_folios` that samples 50 folios within the adapted_working_set window and counts how many were accessed in the last 100ms; if >80% show recent access, lower the dynamic_hot_threshold by 1 (e.g., 3→2 during normal conditions). This data-driven approach builds on the current best program's successful threshold adaptation and could improve small-vs-large throughput by 1-2% by ensuring thresholds remain well-calibrated as working set characteristics shift during the eviction scan.
