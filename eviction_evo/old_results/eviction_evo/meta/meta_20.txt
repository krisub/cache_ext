## Successful Algorithmic Patterns

- **Conservative network pressure detection with multi-signal validation (loss, cwnd, jitter, rcv_wnd) combined with modest multipliers (1.25x vs 1.5x) achieves superior performance across all evaluated programs**: The current best program (Generation 14, score 2182.27) implements four independent pressure signals—packet loss (net_lost > 0 or net_retrans_out > 0), cwnd pressure (packets_out > cwnd/2), high jitter (net_mdev_us > 2ms), and receive-window saturation (net_rcv_wnd < 65536)—with a conservative 1.25x time window multiplier. This approach outperforms all other evaluated programs in the current batch: Generation 15 (sustained_burst_detection, score 2005.09, -8.1%), Generation 16 (working_set_stability_scoring, score 2087.32, -4.3%), Generation 17 (working_set_stability_threshold_adaptation, score 2048.15, -6.2%), Generation 18 (burst_adaptive_hot_threshold, score 1301.77, -40.4%), and Generation 19 (adaptive_jitter_threshold_rtt_scaling, score 1721.48, -21.1%). The multi-signal approach with conservative thresholds (2ms jitter vs 1ms, cwnd/2 ratio) minimizes false positives from transient network jitter while maintaining robust detection of genuine congestion. The 1.25x multiplier (implemented as `(adapted * 5) >> 2`) provides meaningful protection during congestion without over-protecting cache, achieving 1681.15 small-vs-large throughput and 3109.00 congested throughput.

- **Dynamic hot threshold adaptation (HOT_ACCESS_THRESHOLD_PRESSURE=2, HOT_ACCESS_THRESHOLD_NORMAL=3, HOT_ACCESS_THRESHOLD_IDLE=4) decoupled from tier classification enables context-aware protection without over-retention**: The current best program (Generation 14, score 2182.27) implements three distinct hot thresholds that vary based on network pressure and session activity, while maintaining a fixed HOT_ACCESS_THRESHOLD_NORMAL=3 for tier classification. This architectural choice achieves 2.2% higher small-vs-large throughput (1681.15) compared to Generation 15 (1506.40, -10.3%), demonstrating that dynamic threshold adaptation provides finer-grained control than static tier promotion. The decoupling allows the program to classify folios as "warm" (tier 1) at access_count=2 for metadata purposes, while dynamically lowering the eviction protection threshold to 2 during network pressure (treating warm folios as hot for protection) or raising it to 4 during idle periods (aggressively evicting warm folios). Generation 15's survivor tier promotion mechanism (with 0.5x score multiplier for surviving folios) achieves only 2005.09 combined score, 8.1% lower than Generation 14, indicating that static tier promotion is less effective than dynamic threshold adaptation for heterogeneous workload scenarios. The decoupling is critical because it allows independent optimization of metadata tracking (consistent tier classification) and eviction decisions (context-aware thresholds).

- **Adaptive time window scaling with RTT division (÷20) rather than multiplication combined with session-aware idle timeout (5s) prevents over-retention during high-latency conditions**: The current best program (Generation 14, score 2182.27) scales adaptive time windows by adding RTT/20 to the base window (BASE_RECENT_NS=30ms, BASE_WORKING_SET_NS=300ms) rather than multiplying by RTT, achieving superior performance across all evaluated programs. Generation 19 (adaptive_jitter_threshold_rtt_scaling, score 1721.48, -21.1%) implements RTT scaling but with different jitter thresholds and pressure multipliers, resulting in 21.1% lower combined score. The RTT/20 approach prevents excessive cache retention during high-latency conditions—a 100ms RTT adds only 5ms to the 30ms BASE_RECENT_NS window (resulting in 35ms), preventing over-protection while still providing meaningful protection for remote connections. Combined with the 5s NET_IDLE_TIMEOUT_NS, this enables the program to distinguish between active sessions (within 5s) and idle periods, allowing aggressive eviction during idle phases while protecting working sets during active sessions. The session-aware idle timeout is implemented in the eviction callback, allowing per-folio decisions based on current session state rather than static policies. This context-aware approach achieves 3109.00 congested throughput, outperforming Generation 19's 2680.51 by 15.9%, demonstrating that conservative RTT scaling combined with session awareness is more effective than aggressive scaling.

- **Reduced jitter threshold (>2ms vs >1ms) and conservative cwnd pressure ratio (÷2 vs implicit higher ratios) minimize false positives in pressure detection while maintaining robust congestion detection**: The current best program (Generation 14, score 2182.27) uses a high jitter threshold of 2ms (net_mdev_us > 2000000) rather than 1ms, and implements cwnd pressure as (packets_out > cwnd/2) rather than (packets_out * 2 > cwnd). These conservative thresholds achieve 1681.15 small-vs-large throughput and 3109.00 congested throughput. Generation 19 (adaptive_jitter_threshold_rtt_scaling, score 1721.48) implements adaptive jitter thresholds scaled by RTT percentile, but achieves 21.1% lower combined score, suggesting that fixed conservative thresholds are more effective than adaptive jitter scaling for this workload. The 2ms jitter threshold avoids false positives from normal network jitter (typical jitter is 0.5-1ms), while the cwnd/2 ratio ensures that pressure is only detected when packets in flight exceed half the congestion window—a more conservative indicator than (packets_out * 2 > cwnd). This conservative approach minimizes false positives that would trigger over-protective behavior, allowing the program to maintain aggressive eviction during normal conditions while still protecting working sets during genuine congestion. The performance advantage over Generation 19 (15.9% on congested throughput) demonstrates that reducing false positives in pressure detection is more important than adaptive pressure response.

The survivor promotion approach creates a static tier hierarchy (cold/warm/hot) that does not adapt to network conditions, whereas the current best program dynamically adjusts the hot threshold based on network pressure and session activity. Generation 15 achieves only 1506.40 small-vs-large throughput (10.3% lower than Generation 14's 1681.15) and 2997.38 congested throughput (3.6% lower than Generation 14's 3109.00), indicating that static tier promotion over-protects warm folios during network pressure, reducing eviction aggressiveness and degrading throughput.
