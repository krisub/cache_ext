- **Adaptive eviction thresholds (base 60, raised to 70 under pressure, lowered to 40 when idle, +10 during bursts) provide superior workload-aware policy tuning**: The current best program dynamically adjusts the eviction threshold based on network conditions and session state, achieving 1645.52 ops/sec on small-vs-large workloads—the highest among all evaluated programs (Generation 6: 1489.91, -9.4%; Generation 7: 1613.83, -1.9%; Generation 8: 1216.50, -26.0%; Generation 9: 1119.32, -31.9%). # Actionable Recommendations for Future Program Mutations

1. **Implement dynamic access count thresholds that adapt to network pressure conditions**
   Currently, HOT_ACCESS_THRESHOLD is fixed at 3, but the current best program's exceptional performance under pressure (3152.17 ops/sec) suggests that tier classification itself should be network-aware. During high-pressure periods (loss, cwnd pressure, high jitter), lower the hot threshold to 2 to treat more folios as protective; during idle periods, raise it to 4 to aggressively evict rarely-accessed folios. This extends the successful multi-factor scoring approach by making tier classification dynamic rather than static, potentially improving both congested throughput (by protecting more of the working set during pressure) and small-vs-large throughput (by aggressive eviction during idle phases).

2. **Refine burst detection to use packet count velocity in addition to inter-arrival timing**
   The current burst detection relies solely on inter-arrival time (< 10ms), but this can miss sustained high-frequency workloads that don't have consistent sub-10ms spacing. Add a secondary burst signal: if net_recv_count increases by more than 15 packets within a 100ms sliding window, classify as "sustained burst" and apply a more aggressive 0.4x multiplier (vs. current 0.5x) to recently-accessed folios (age < 500ms). This would complement the existing inter-arrival detection and better distinguish between transient spikes and sustained load, potentially improving P99 latency during congested scenarios while maintaining the current best program's 3152.17 congested throughput.

3. **Introduce a secondary "survivor promotion" tier for folios that survive multiple eviction scans without being accessed**
   While Generation 6's survivor promotion underperformed (-8.0%), the current best program's success suggests that a more conservative promotion mechanism could work. Implement a lightweight promotion: track how many consecutive eviction scans each folio survives (without being accessed), and after 5+ scans, apply a permanent 0.6x score multiplier to prevent thrashing. This differs from Generation 6's approach by only promoting folios that survive *without* being re-accessed, targeting the specific case of working-set folios that are evicted and re-faulted repeatedly, potentially reducing P99 latency by 5-10% during sustained congestion.

4. **Add receive-window saturation as a fifth network pressure signal with conservative thresholds**
   The current program detects pressure via loss, cwnd ratio, jitter, and RTT, but doesn't monitor receive-window exhaustion—a class of network congestion (receiver-side backpressure) that could warrant protective eviction. Add a fifth pressure signal: if net_rcv_wnd is below 32KB (indicating receiver buffer pressure), apply the 0.75x protective multiplier. This is more conservative than Generation 7's 65KB floor (which degraded performance by 2.7%), and targets only severe receiver-side backpressure, potentially improving robustness during asymmetric workloads without the false positives that hurt Generation 7.

5. **Implement adaptive eviction threshold scaling based on folio age distribution within the current scan**
   The current fixed thresholds (base 60, 70 under pressure, 40 idle, +10 during bursts) don't account for the actual age distribution of folios in the list. Add a pre-scan pass that samples 100 random folios to compute the median age, then scale the eviction threshold dynamically: if median age is very high (> 500ms), lower the threshold by 10 to evict more aggressively; if median age is very low (< 50ms), raise the threshold by 10 to protect the working set. This data-driven approach builds on the current best program's successful threshold adaptation and could improve small-vs-large throughput by 2-3% by ensuring thresholds remain well-calibrated as workload characteristics shift.
