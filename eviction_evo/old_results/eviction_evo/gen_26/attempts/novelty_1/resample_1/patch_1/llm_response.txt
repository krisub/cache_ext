# Analysis

Looking at the performance progression:
- Prior best: **2182.27** (dual_small_vs_large: 1681.15, dual_congested: 3109.00)
- Current program: **2087.32** (dual_small_vs_large: 1588.39, dual_congested: 3043.24)

The current program has **regressed by ~95 points** compared to the prior best. The issue is the working-set stability tracking:

1. The `eviction_scan_stats` logic has a subtle bug: `in_working_set_stable` is defined as `age_stable < STABILITY_RECENT_NS`, and then both counters are incremented together in the same branch, making the stability ratio always ~100%, defeating the adaptive threshold mechanism.

2. The stability calculation happens *during* iteration, causing the threshold to be time-varying within a single eviction pass, which is unstable.

3. The prior best program (2182.27) was simpler and more effective, using fixed thresholds with network-aware adjustments.

## Proposed Fix

Implement the **recency boost** recommendation: add a mechanism that temporarily improves protection for folios accessed within the last **10ms**, treating them as if they have +1 access count for threshold comparison. This targets frequently-accessed small folios that fall just below the hot threshold.

Additionally, remove the buggy stability tracking and return to a simpler, more stable eviction strategy.

// -- Helper: get dynamic hot threshold based on working set stability --------
static __always_inline u32 get_hot_threshold_by_stability(void)
{
    u32 stats_key = 0;
    struct eviction_scan_stats *stats =
        bpf_map_lookup_elem(&eviction_scan_stats_map, &stats_key);

    if (!stats || stats->protected_in_window == 0)
        return HOT_ACCESS_THRESHOLD;

    // Calculate stability ratio: (recently accessed in window / total in window) * 100
    u32 stability = (stats->recent_in_window * 100) / stats->protected_in_window;

    // If working set is stable (>80% of protected folios recently accessed),
    // lower the hot threshold by 1 to be more protective
    if (stability > STABILITY_HIGH_RATIO) {
        // Lower threshold promotes warm folios to "hot" protection
        return (HOT_ACCESS_THRESHOLD > 1) ? (HOT_ACCESS_THRESHOLD - 1) : 1;
    }

    return HOT_ACCESS_THRESHOLD;
}
