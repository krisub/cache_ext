<DESCRIPTION>
The current program uses a fixed 2ms jitter threshold to detect network pressure, but jitter significance is RTT-dependent. On a 10ms RTT connection, 2ms jitter represents 20% variability (severe). On a 100ms RTT connection, 2ms is only 2% variability (negligible). This causes false positives on low-latency connections and false negatives on high-latency connections.

The proposed change implements adaptive jitter threshold scaling that accounts for RTT context:
- Base threshold: 2ms (appropriate for ~100ms RTT connections)
- Scaling: Multiply by (true_RTT / 100ms) to get RTT-proportional threshold
- Clamping: Bound result to [1ms, 4ms] to avoid extremes

This prevents the policy from overprotecting during genuinely stable high-latency periods (improving throughput on dual_congested by ~2-3%) while maintaining correct pressure detection on low-latency connections (preserving dual_small_vs_large performance).

Implementation details:
1. Extract true RTT by dividing net_srtt_us by 8 (kernel stores srtt<<3)
2. Scale 2ms baseline by (true_RTT_us / 100000us)
3. Clamp to [1000000, 4000000] microseconds (1-4ms range)
4. Use scaled threshold for high_jitter detection

Expected improvement: ~0.5-1.5% combined score by reducing false positives in dual_congested trace.
</DESCRIPTION>
