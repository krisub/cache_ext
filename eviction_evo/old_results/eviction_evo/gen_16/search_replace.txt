<DESCRIPTION>
The current scoring-based eviction policy uses fixed hot access thresholds (HOT_ACCESS_THRESHOLD = 3), but the working set characteristics vary significantly across workloads. The dual_small_vs_large trace (fast reader + slow writer with zipfian distribution) particularly suffers when we can't distinguish between a small concentrated hot set vs. a diffuse warm set.

The recommendation is to add "working set stability" detection: measure whether folios we're protecting are actually being reused. If a high percentage (>80%) of folios within the protected window are recently accessed (within last 100ms), the working set is "stable and hot" - we should lower the hot threshold to be more protective. If stability is low, we keep normal thresholds.

Implementation approach:
1. Add a map to track eviction scan statistics (protected folios seen vs recently accessed)
2. During eviction iteration, accumulate these statistics for folios in the working set window
3. After partial scan (to avoid BPF loop limits), compute stability ratio
4. Adjust the hot threshold downward (by 1) if stability > 80%
5. This helps the dual_small_vs_large trace by better protecting the zipfian hot set while still aggressively evicting the cold slow-writer pages

This data-driven threshold adaptation should improve small_vs_large throughput (currently 1645.52) toward 1680+, while maintaining or improving congested trace performance.
</DESCRIPTION>

static __always_inline u64 get_adaptive_window(u64 base_ns, bool under_pressure)
{
    u64 adapted = base_ns;

    // Scale by RTT: higher RTT = longer windows (each miss is more expensive)
    // Clamp net_srtt_us to avoid overflow; assume max ~10ms RTT for scaling
    u32 rtt_clamped = (net_srtt_us > 10000000) ? 10000000 : net_srtt_us;

    if (under_pressure) {
        adapted = (adapted * 3) >> 1;  // 1.5x multiplier

// -- Helper: get dynamic hot threshold based on working set stability --------
static __always_inline u32 get_hot_threshold_by_stability(void)
{
    u32 stats_key = 0;
    struct eviction_scan_stats *stats =
        bpf_map_lookup_elem(&eviction_scan_stats_map, &stats_key);

    if (!stats || stats->protected_in_window == 0)
        return HOT_ACCESS_THRESHOLD;

    // Calculate stability ratio: (recently accessed in window / total in window) * 100
    u32 stability = (stats->recent_in_window * 100) / stats->protected_in_window;

    // If working set is stable (>80% of protected folios recently accessed),
    // lower the hot threshold by 1 to be more protective
    if (stability > STABILITY_HIGH_RATIO) {
        // Lower threshold promotes warm folios to "hot" protection
        return (HOT_ACCESS_THRESHOLD > 1) ? (HOT_ACCESS_THRESHOLD - 1) : 1;
    }

    return HOT_ACCESS_THRESHOLD;
}
