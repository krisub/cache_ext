## Analysis

1. **Fixed time windows don't adapt to network conditions**: The 100ms and 1s windows are generic but both workloads have different network characteristics:
   - `dual_small_vs_large`: Mixed direct/delayed clients
   - `dual_congested`: Both clients behind 2-5ms delays with limited bandwidth
   
2. **No loss/congestion reaction**: The policy ignores `net_lost`, `net_retrans_out`, and cwnd pressure. When the network is degraded, every cache miss is MORE expensive, so we should be MORE aggressive about protection.

3. **No burst detection**: The inter-arrival time (last_packet_ts - net_prev_packet_ts) could indicate request bursts. During bursts, we should protect more pages.

4. **Unused network metrics**: We have RTT, jitter, cwnd, packets_out available but only use packet timestamp. RTT scales how costly a miss is - high RTT means longer protection windows.

## Proposed Improvements

I'll add:
1. **RTT-aware adaptive time windows** - Scale protection windows based on network latency
2. **Congestion detection** - Tighten eviction when packets are lost or being retransmitted
3. **Burst detection** - Protect more during request bursts
4. **Jitter-aware tier promotion** - Be conservative when network is unstable

// -- Helper: compute adaptive time window based on network conditions --------
static __always_inline u64 get_adaptive_window(u64 base_ns, bool under_pressure)
{
    u64 adapted = base_ns;
    
    // Scale by RTT: higher RTT = longer windows (each miss is more expensive)
    // Clamp net_srtt_us to avoid overflow; assume max ~10ms RTT for scaling
    u32 rtt_clamped = (net_srtt_us > 10000000) ? 10000000 : net_srtt_us;
    adapted = adapted + (u64)rtt_clamped / 10;
    
    // If network is under pressure (loss, retrans, high jitter), increase window
    if (under_pressure) {
        adapted = (adapted * 3) >> 1;  // 1.5x multiplier
    }
    
    return adapted;
}

## Rationale

1. **RTT-aware scaling**: When RTT is high (dual_congested has 2-5ms delays), each page miss is more costly, so we protect pages longer. The adaptation is linear: `adapted = base + (rtt_us / 10)`, which doubles the window for ~10ms RTT.

2. **Congestion detection**: Three indicators:
   - `net_lost > 0 or net_retrans_out > 0`: packets being lost → network unstable
   - `packets_out > cwnd/2`: more packets in flight than safe cwnd → bottleneck
   - `net_mdev_us > 1ms`: jitter indicates unstable timing
   
   When any of these occur, we extend protection windows by 1.5x.

3. **Burst detection**: When `inter_arrival < 10ms`, it's a burst of requests. During bursts, we further extend protection (1.5x) because the working set is hot.

4. **Conservative during congestion**: All three multipliers (RTT, pressure, burst) are multiplicative, so the policy becomes progressively more conservative as network conditions degrade—exactly when we need it most.

This approach should improve throughput on both traces by:
- **dual_small_vs_large**: Better handling of the slow writer (detects it as burst) while protecting reader's working set
- **dual_congested**: Aggressive protection when network has delays/congestion, since there's measurable loss and latency
