<DESCRIPTION>
Replace the current binary hot/very-hot threshold system in the high-priority eviction callback with a graduated protection multiplier that scales smoothly from 2× to 3× based on access frequency. This provides finer-grained protection for folios with moderate access counts (4-5 accesses), which currently receive the same 2× protection as barely-hot folios (2-3 accesses).

The new system:
- access_count >= 6: 3.0× protection (unchanged)
- access_count >= 4: 2.5× protection (NEW - previously lumped with 2× tier)
- access_count >= 2: 2.0× protection (unchanged)
- access_count < 2: 1.0× baseline (unchanged)

This graduated approach should reduce eviction of moderately-hot pages, improving cache hit rates for the file_priority workload where access patterns have intermediate hotness levels. By using integer arithmetic (multiplying by 250 then dividing by 100 for 2.5×), we maintain BPF verifier compatibility while achieving smooth protection scaling.

This change addresses the gap between the current binary 2×/3× thresholds by adding an intermediate tier, which should improve throughput by 1-2% through better retention of medium-frequency pages.
</DESCRIPTION>
