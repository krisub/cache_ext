sample-based-high-prio-eviction
</NAME>

<DESCRIPTION>
The current implementation iterates through the entire high-priority list during every eviction event. This callback overhead can accumulate, especially under memory pressure when evictions are frequent. By switching to probabilistic sampling of the high-priority list (via `bpf_cache_ext_list_sample()` instead of `bpf_cache_ext_list_iterate()`), we reduce the number of callbacks executed while still allowing selective eviction of high-priority pages when necessary.

The recommendation suggests using a ratio of 0.2 (sample 20% of high-priority folios randomly). This balances:
- **Reduced overhead**: Sample-based iteration processes fewer folios, lowering callback costs
- **Maintained protection**: Most high-priority pages remain untouched in each eviction pass
- **Adaptive pressure handling**: Under high memory pressure, multiple eviction passes will gradually sample different folios, achieving eventual eviction of aged high-priority pages

This should yield 1-2% throughput improvement by reducing per-eviction latency while preserving the protective benefits of priority-aware segregation.
</DESCRIPTION>
