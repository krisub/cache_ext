adaptive_demotion_under_contention

<DESCRIPTION>
The recommendation suggests implementing adaptive demotion thresholds that tighten under CPU contention to reclaim high-priority slots faster during peak load. Currently, the program lacks a demotion mechanism entirely, and the file_niceness trace (which tests priority adaptation) shows slightly lower throughput than file_priority.

The key insight is that single-access folios on the high-priority list that have aged beyond the working set consume valuable high-prio cache slots that should be available for truly hot high-priority pages. Under high CPU contention (when many tasks are runnable), we should demote these cold single-access pages more aggressively to free slots for active high-priority working set.

Changes:
1. Add a HIGH_CONTENTION_THRESHOLD constant (6 runnable tasks = high load)
2. Add a DEMOTION_AGE_BASE constant for the baseline demotion threshold (2x working set = 600ms)
3. Implement demotion logic in `bpf_evict_high_prio_cb` that:
   - Demotes single-access folios that are older than DEMOTION_AGE_BASE
   - Under contention, tightens this to 1.5x working set (450ms) to reclaim slots faster
4. Track demotions via bump_counter(7) for observability

This should improve file_niceness throughput during priority transitions while maintaining file_priority performance, improving the harmonic mean.
</DESCRIPTION>

// -- Eviction callback for high-priority list (protect aggressively) --------
static int bpf_evict_high_prio_cb(int idx, struct cache_ext_list_node *node)
{
    u64 now = bpf_ktime_get_ns();
    u64 key = (u64)node->folio;

    struct sched_folio_metadata *meta =
        bpf_map_lookup_elem(&folio_metadata_map, &key);

    if (!meta)
        return CACHE_EXT_EVICT_NODE;

    // Never evict dirty/writeback pages
    if (folio_test_dirty(node->folio) || folio_test_writeback(node->folio))
        return CACHE_EXT_CONTINUE_ITER;

    u64 age = now - meta->last_access_ts;

    // Adaptive thresholds based on CPU contention
    u32 hot_threshold = HOT_ACCESS_THRESHOLD;
    u32 very_hot_threshold = VERY_HOT_ACCESS_THRESHOLD;

    if (sched_nr_running > CPU_BUSY_THRESHOLD) {
        // Under contention: lower thresholds even more to protect working set aggressively
        very_hot_threshold = 3;
    }

    // Very hot folios: protect aggressively
    if (meta->access_count >= very_hot_threshold) {
        if (age < WORKING_SET_NS * 3)
            return CACHE_EXT_CONTINUE_ITER;
    }

    // Hot folios (even single access): protect well to maintain working set
    if (meta->access_count >= hot_threshold) {
        if (age < WORKING_SET_NS * 2)
            return CACHE_EXT_CONTINUE_ITER;
    }

    // Small files from high-priority: extend protection window
    bool is_small = should_protect_small_file(node->folio);
    if (is_small) {
        if (age < WORKING_SET_NS * 2)
            return CACHE_EXT_CONTINUE_ITER;
    }

    // When CPU is busy, protect high-prio working set aggressively
    if (sched_nr_running > CPU_BUSY_THRESHOLD) {
        if (age < WORKING_SET_NS)
            return CACHE_EXT_CONTINUE_ITER;
    }

    // Recently accessed: protect
    if (age < RECENT_ACCESS_NS)
        return CACHE_EXT_CONTINUE_ITER;

    // Only evict if very old
    if (age < WORKING_SET_NS)
        return CACHE_EXT_CONTINUE_ITER;

    return CACHE_EXT_EVICT_NODE;
}
