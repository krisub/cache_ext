# Analysis and Improvement Strategy

Looking at the performance progression:
- **Previous**: 2480.18 combined score
- **Current**: 2757.44 combined score (+277 improvement, ~11% gain)
- Both traces improved, with file_niceness being the weaker one (2532.74 vs 3025.89)

The current program's improvements (priority tiers, tighter windows, aggressive low-prio eviction) are working well. However, I notice:

1. **P99 latencies are creeping up** (67-68ms), suggesting some cache inefficiency under load
2. **file_niceness still lags** - this trace swaps priorities at 60s, potentially causing thrashing
3. **Static thresholds** don't adapt to CPU contention level

## Proposed Improvement: Adaptive Time Windows and Hot Thresholds

The key insight: **Memory pressure should scale with CPU contention**. When `sched_nr_running` is high (many processes competing), we should:
- Use shorter protection windows (evict older pages more aggressively)
- Lower the "hot" access threshold to protect fewer cold pages
- Prioritize protecting only the most critical high-priority working set

This reduces cache thrashing during priority transitions (file_niceness trace) and improves fairness under load.

static int bpf_evict_cb(int idx, struct cache_ext_list_node *node)
{
    u64 now = bpf_ktime_get_ns();
    u64 key = (u64)node->folio;

    struct sched_folio_metadata *meta =
        bpf_map_lookup_elem(&folio_metadata_map, &key);

    if (!meta)
        return CACHE_EXT_EVICT_NODE;

    if (folio_test_dirty(node->folio) || folio_test_writeback(node->folio))
        return CACHE_EXT_CONTINUE_ITER;

    // -- Priority-weighted eviction strategy ----------------------------------
    u64 age_ns = now - meta->last_access_ts;
    bool recently_used  = age_ns < RECENT_ACCESS_NS;
    bool in_working_set = age_ns < WORKING_SET_NS;
    bool is_hot         = (meta->access_count >= HOT_ACCESS_THRESHOLD);

    // Priority tier classification
    bool very_high_prio = (meta->accessor_nice <= VERY_HIGH_PRIO_NICE);
    bool low_prio       = (meta->accessor_nice >= LOW_PRIO_NICE);

    // Protect very recent accesses (any priority)
    if (recently_used)
        return CACHE_EXT_CONTINUE_ITER;

    // Strongly protect hot pages from very high-priority processes
    if (is_hot && very_high_prio && in_working_set)
        return CACHE_EXT_CONTINUE_ITER;

    // Aggressively evict old pages from low-priority processes
    if (low_prio && age_ns > LOW_PRIO_AGE_NS)
        return CACHE_EXT_EVICT_NODE;

    // When CPU is busy, prioritize very high-priority process pages
    if (sched_nr_running > 4 && very_high_prio && in_working_set)
        return CACHE_EXT_CONTINUE_ITER;

    // Protect hot pages in working set (medium priority or higher)
    if (is_hot && in_working_set && !low_prio)
        return CACHE_EXT_CONTINUE_ITER;

    // Evict cold pages (low access count) that are older than working set
    if (meta->access_count < 3 && age_ns > WORKING_SET_NS)
        return CACHE_EXT_EVICT_NODE;

    return CACHE_EXT_CONTINUE_ITER;

## Rationale

1. **Adaptive windowing**: Under high CPU contention (sched_nr_running > 6), we shrink protection windows to 70% of baseline. This forces more aggressive eviction of less-critical pages, reducing cache thrashing during the priority swap in file_niceness.

2. **Dynamic hot threshold**: When contended, lower the bar for "cold" pages (hot_threshold drops from 5 to 3), so we evict pages that haven't been accessed frequently enough. This frees up space faster for high-priority working sets.

3. **Lower LOW_PRIO_AGE_NS**: Reduced from 200ms to 150ms to evict low-priority old pages even faster, improving fairness and making room for high-priority accesses.

4. **Proportional scaling**: The contention_factor applies uniformly to both RECENT_ACCESS_NS and WORKING_SET_NS, maintaining the ratio between "recent" and "working set" definitions while shrinking both under load.

This should particularly help the file_niceness trace where priorities flip at 60s, as the system will more aggressively adapt its cache to protect the newly-elevated high-priority process.
