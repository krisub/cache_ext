<DESCRIPTION>
Implement a promotion mechanism that moves frequently-accessed low-priority folios to the high-priority list when they demonstrate high access counts.

**Rationale:** The current dual-list strategy segregates folios by the accessor's *initial* priority (nice value at time of first access). However, a folio's *access pattern* is often a better predictor of cache value than initial priority. A low-priority process that repeatedly accesses certain files creates a hot working set that deserves protection, even though the process has low CPU priority.

By promoting low-priority folios with access_count >= 8 to the high-priority list, we capture the insight that reuse frequency trumps scheduling priority for cache retention decisions. This should:
1. Reduce thrashing for low-priority processes with sequential/repetitive access patterns
2. Better protect true working sets regardless of their accessor's nice value
3. Improve the weaker file_niceness trace (currently 2510.52) where priority can change mid-run, benefiting from adaptive promotion

The mechanism uses only existing metadata fields: if a folio from a low-priority accessor accumulates 8+ accesses (indicating a hot pattern), it gets promoted to the high-priority list where it receives stronger eviction protection. This is a form of adaptive tiering based on observed access patterns.

**Expected impact:** 2-3% improvement on combined score, primarily by boosting the file_niceness trace where dynamic priority changes benefit from promotion of hot patterns.
</DESCRIPTION>
