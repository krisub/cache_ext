<DESCRIPTION>
The current program uses fixed global thresholds for determining folio "heat" (1s for hot, 10s for cold). This proposal implements adaptive thresholds based on each folio's own access pattern history using the interval_minmax listener data that we're already tracking.

**Rationale**: Different folios have different natural access patterns. A folio accessed every 100ms shouldn't be treated the same as one accessed every 5s using the same global threshold. By using each folio's min/max inter-access intervals, we can detect when a folio is "hot" (accessing near its historical minimum) vs "cold" (accessing near its historical maximum) relative to its own pattern rather than a global constant.

**Implementation**: 
1. Use the per-folio `interval_minmax.min_val` and `interval_minmax.max_val` to define a range
2. If `interval_ewma` is in the lower 25% of the range (closer to min), mark as hot
3. If `interval_ewma` is in the upper 75% of the range (closer to max), mark as cold
4. Fall back to fixed thresholds only if minmax data is unavailable or invalid

This makes the heat scoring workload-adaptive rather than using hard-coded time constants.

**Additional improvement**: Tighten the recency window from 5 seconds to 2 seconds. Looking at the prior programs, the one with a 2-second recency window (program 2) performed well. A tighter window better identifies truly recent accesses in the fast-paced network workload.
</DESCRIPTION>
