# Program Evaluation Analysis

## Successful Algorithmic Patterns

- **Multi-factor scoring with network-aware protection thresholds**: The current best program (Generation 1, score 1977.84) combines access frequency with RTT-based protection multipliers (1.0x–1.5x) triggered at specific thresholds (>5ms, >10ms). This outperforms the pure LFU baseline (Generation 0, score 1965.52) by +12.32 points and significantly exceeds the burst-detection variant (Generation 2, score 1480.42, -497.42 points). The RTT threshold approach provides measurable protection without excessive overhead—the early-exit kprobe check ensures zero cost when listeners are disabled, matching baseline performance while enabling dynamic adaptation.

- **Selective listener enablement with minimal overhead**: Generation 1 enables only three listeners (EWMA for GF_SRTT_US and GF_PACKETS_OUT, MinMax for GF_LOST) rather than attempting comprehensive network monitoring. This targeted approach achieves the highest combined score (1977.84) while maintaining stability (dual_congested std: 66.84 MB/s). In contrast, Generation 2's burst-detection mechanism (which adds inter-packet arrival tracking) drops to 1480.42, suggesting that overly granular network signals introduce noise without proportional benefit.

- **Recency bonuses with fixed time windows**: The current best program applies a 5-second recency window bonus (+50 points) to recently accessed pages, combined with per-folio EWMA interval tracking. This temporal locality signal complements frequency-based scoring and protects working sets during congestion. Generation 3 (score 1868.97) uses a 2-second window and achieves lower performance (-109 points vs. Generation 1), indicating that the 5-second window better captures LevelDB's access patterns.

- **LevelDB-specific structural protection**: All successful programs (Gen 0–3) protect the last page of files (index blocks) with S64_MAX or high bonus scores (+100000 in Gen 1). This structural hint is critical for LevelDB workloads and contributes to consistent performance across all passing variants. The protection is lightweight (single conditional check) and provides semantic awareness without network overhead.

## Ineffective Approaches

- **Burst detection via inter-packet arrival times**: Generation 2 (score 1480.42) implements burst protection by detecting low inter-arrival patterns (<100µs) and applying +5000 boost when triggered. This approach underperforms by -497.42 points vs. the best program, suggesting that packet-level granularity introduces false positives or misses the actual congestion signal. The feedback notes that "burst detection effectively protects active working sets," yet the score decline indicates the mechanism either fires too frequently (evicting useful pages) or too rarely (missing protection opportunities). The inter-packet arrival EWMA may be too noisy for cache eviction decisions.

- **Aggressive congestion ratio calculations with unsigned division constraints**: Generation 4 attempted to calculate a congestion ratio via `(packets_out_ewma * 100) / cwnd_ewma` but failed compilation due to BPF's lack of signed division support. This reveals a fundamental constraint: complex ratio-based scoring requires either unsigned arithmetic, lookup tables, or restructured logic. The failure (score 0.00) demonstrates that algorithmic sophistication must respect BPF ISA limitations; the design was sound but uncompilable.

- **Excessive per-folio metadata tracking without clear scoring benefit**: Generation 2 and 3 both enable per-folio MinMax and EWMA listeners for interval tracking, yet Generation 1 (which also enables these) achieves higher scores. The difference suggests that enabling listeners alone is insufficient—the scoring function must effectively translate interval signals into eviction decisions. Generation 2's attempt to use interval_ewma as a recency penalty (subtracting `interval_ewma / 100000`) may have been too aggressive or poorly calibrated, leading to suboptimal victim selection.

- **Loss-based penalties without threshold tuning**: Generation 1 applies an additional 30% boost when `max_lost > 0`, but this binary trigger may be overly sensitive. Generation 3's approach (which also detects loss) achieves 1868.97 vs. 1977.84, suggesting that loss detection alone provides marginal benefit unless carefully integrated with other signals. The lack of loss-rate thresholds or decay mechanisms may cause sustained over-protection even after transient loss events.

## Implementation Insights

- **Early-exit kprobe optimization is critical for baseline parity**: The current best program (and all passing variants) include an early-exit check in the tcp_recvmsg kprobe that returns immediately if no listeners are enabled. This ensures zero overhead when network monitoring is disabled, matching the non-instrumented baseline (Generation 0, score 1965.52). The kprobe is conditionally compiled (`#if 1` in the provided code) and can be disabled entirely for pure LFU behavior. This architectural separation allows safe evolution—the infrastructure is fixed, but the policy (gf_configs, folio_cfg, bpf_score_fn) can be evolved without modifying networking code.

- **Fixed-point arithmetic for network factor calculations**: Generation 1 uses fixed-point multiplication/division (e.g., `(base_score * network_factor) / 100`) to apply protection multipliers without floating-point operations. This is BPF-compatible and avoids the signed division trap that caught Generation 4. The network_factor variable (100 = 1.0x, 150 = 1.5x) is computed via conditional branches on RTT thresholds, making the logic transparent and debuggable. This pattern is replicated in all passing programs and appears essential for reliable BPF compilation.

- **Per-folio metadata initialization and lazy loading**: The current best program initializes per-folio metadata via `vulcan_folio_init(bpf_ktime_get_ns())` in both `folio_added` and `folio_accessed` callbacks, with lazy initialization if metadata is missing. This ensures that every tracked folio has valid timestamps and listener state, preventing null-pointer dereferences or stale data. The metadata map uses folio pointer as key (`u64 key = (u64)folio`), enabling O(1) lookups during eviction scoring.

- **Vulcan listener dispatch layer abstracts feature complexity**: The code includes `#include "vulcan_bpf/vulcan_feature.h"` which provides `vulcan_update_feature()` and accessor functions (`vulcan_get_ewma()`, `vulcan_get_max()`, etc.). This abstraction allows the scoring function to call `vulcan_get_ewma(GF_SRTT_US)` without knowing which map or listener state to access. The dispatch is controlled by `gf_configs[]` array, enabling per-feature listener configuration. This design allows evolution of scoring logic without modifying the listener infrastructure, reducing the risk of introducing bugs in the fixed networking code.

# Actionable Recommendations for Future Program Mutations

1. **Refine RTT threshold granularity with intermediate protection levels**: The current best program uses two RTT thresholds (5ms and 10ms) with fixed multipliers (1.25x and 1.5x). Experiment with adding a third threshold at 7-8ms with a 1.35x multiplier, or test non-linear scaling (e.g., `network_factor = 100 + (srtt_ewma / 10000)` capped at 150) to better capture the continuous relationship between RTT and cache miss cost. This builds on the proven RTT-threshold approach while exploring whether finer granularity yields better harmonic scores across mixed workloads.

2. **Integrate packets-in-flight (PACKETS_OUT EWMA) as a congestion signal into the network factor calculation**: The current program enables PACKETS_OUT EWMA but does not use it in the scoring function. Add a secondary congestion check: if `packets_out_ewma > cwnd_ewma * 0.8` (indicating high utilization), apply an additional 1.1x boost to the network_factor. This leverages the already-enabled listener and provides a complementary signal to RTT for detecting network stress without adding new kprobe overhead.

3. **Calibrate the recency window and interval-based heat scoring with adaptive thresholds**: The 5-second recency window and interval EWMA thresholds (1s for hot, 10s for cold) are fixed. Test a data-driven approach: compute the median inter-access interval from the per-folio EWMA listener and use it as a dynamic threshold (e.g., hot if `interval_ewma < 2 * median`, cold if `interval_ewma > 10 * median`). This could improve working-set protection by adapting to workload-specific access patterns rather than using fixed time windows.

4. **Explore loss-rate decay to avoid sustained over-protection after transient loss events**: The current program applies a 30% boost whenever `max_lost > 0`, which may persist long after a brief loss spike. Implement a time-decay mechanism: track the timestamp of the last loss event and only apply the boost if loss occurred within the last 100ms (or scale the boost by `exp(-time_since_loss / decay_constant)`). This prevents the loss signal from stale-locking the cache into overly conservative eviction after transient congestion.

5. **Test per-folio access-count normalization to reduce bias toward long-lived folios**: The current base_score is simply `access_count`, which favors folios that have been in cache longer regardless of recent activity. Normalize by dividing by `(now - folio_creation_time)` to compute an access rate, or use a recency-weighted access count: `access_count * exp(-(now - last_access_ts) / time_constant)`. This could improve victim selection by prioritizing recently-active folios over old, infrequently-accessed ones, especially under memory pressure.
