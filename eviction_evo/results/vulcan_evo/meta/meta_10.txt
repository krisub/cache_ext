# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

# Program Evaluation Analysis

## Successful Algorithmic Patterns

- **Selective three-listener configuration (SRTT EWMA, PACKETS_OUT EWMA, LOST MinMax) achieves highest performance**: The current best program (Generation 5, score 1977.84) enables exactly three global feature listeners with carefully tuned EWMA alpha values (150 for SRTT_US, 200 for PACKETS_OUT) and MinMax for loss detection. This targeted approach outperforms the baseline (Generation 0, 1965.52) by +12.32 points and significantly exceeds more complex variants like Generation 2 (1480.42, -497.42 points). The selective enablement strategy demonstrates that network-aware protection effectiveness depends on signal quality and relevance, not listener count. The kprobe early-exit optimization (checking `any_enabled` flag before processing) ensures this configuration incurs zero overhead when disabled, maintaining baseline parity while enabling dynamic adaptation.

- **Fixed-point RTT threshold-based protection multipliers (1.25x at >5ms, 1.5x at >10ms) with loss-triggered 30% boost**: Generation 5's scoring function applies multiplicative network factors computed via conditional branches on absolute RTT thresholds rather than relative trends or complex ratios. The two-tier RTT protection (125 and 150 fixed-point factors) combined with loss-triggered additional 30% boost provides clear, debuggable protection logic that avoids BPF arithmetic constraints. This approach outperforms Generation 3's RTT trend detection (1868.97, -109 points), indicating that absolute network state is a more reliable signal than relative changes for cache eviction decisions. The fixed-point arithmetic (`(base_score * network_factor) / 100`) is BPF-compatible and avoids the signed division failures that plagued Generations 7 and 8.

- **Per-folio EWMA interval tracking (alpha=250) with dual-threshold heat scoring (hot: <1s, cold: >10s)**: Generation 5 enables both MINMAX and EWMA listeners on per-folio intervals via `folio_cfg`, then applies asymmetric heat bonuses in the scoring function: +100 points for hot folios (interval_ewma < 1 second) and -100 points for cold folios (interval_ewma > 10 seconds). This dual-threshold approach captures temporal locality without requiring complex calculations. The high EWMA alpha (250) provides responsive interval tracking that reflects recent access patterns. Combined with the 5-second recency window bonus (+50 points), this creates a multi-scale temporal protection strategy that balances working-set retention with efficient victim selection.

- **LevelDB-specific structural protection (last page index block with +100k bonus) combined with recency window (5 seconds, +50 points)**: Generation 5 protects the last page of files (LevelDB index blocks) with a fixed +100,000 score bonus, ensuring these critical metadata pages are rarely evicted. This structural hint is paired with a 5-second recency window that adds +50 points to recently accessed pages. The combination of semantic (file structure) and temporal (recency) protection signals provides robust working-set retention during both normal and congested operation. Generation 3's use of a 2-second recency window (1868.97, -109 points vs. best) confirms that the 5-second window better captures LevelDB's access patterns, suggesting that the window duration is calibrated to typical LevelDB block reuse intervals.

## Ineffective Approaches

- **Burst detection via inter-packet arrival times (<100µs threshold with +5000 boost) introduces false positives and reduces throughput**: Generation 2 (score 1480.42, -497.42 points vs. best) implements burst protection by detecting low inter-arrival patterns and applying a +5000 score boost. Despite the feedback noting that "burst detection effectively protects active working sets," the actual performance decline indicates the mechanism either fires too frequently (over-protecting pages and reducing cache efficiency) or too rarely (missing actual bursts). The inter-packet arrival EWMA signal appears too fine-grained for cache eviction decisions—packet-level granularity does not correlate reliably with page-level access patterns. The +5000 boost magnitude may also be poorly calibrated relative to base frequency scores, causing inappropriate victim selection.

- **Complex congestion ratio calculations with unsigned division constraints cause compilation failures**: Generations 7 and 8 both attempted to calculate congestion ratios via `(packets_out_ewma * 100) / cwnd_ewma` or `(base_score * network_factor) / 100` with signed operands, resulting in BPF compiler rejection (clang-14 and LLVM 14 both reject signed division) and score 0.00. While the architectural design was sound (network metrics properly configured with EWMA/RollingWindow listeners, kprobe early-exit optimization, per-folio metadata tracking), the implementation violated BPF backend constraints. This reveals a fundamental limitation: algorithmic sophistication must respect BPF ISA constraints. The failures demonstrate that complex ratio-based scoring requires either unsigned arithmetic throughout, lookup tables, or restructured logic to avoid signed division operations.

- **Excessive per-folio metadata tracking without effective scoring integration reduces performance**: Generations 2 and 3 both enable per-folio MinMax and EWMA listeners for interval tracking, yet Generation 1 (which also enables these listeners) achieves higher scores (1977.84 vs. 1868.97 for Gen 3). The difference suggests that enabling listeners alone is insufficient—the scoring function must effectively translate interval signals into eviction decisions. Generation 2's attempt to use interval_ewma as a recency penalty (subtracting `interval_ewma / 100000`) may have been too aggressive or poorly calibrated, leading to suboptimal victim selection. The per-folio metadata infrastructure is necessary but only valuable when the scoring function applies it with appropriate thresholds and magnitudes.

- **Loss-based penalties without threshold tuning or decay mechanisms cause sustained over-protection**: While Generation 5 applies an additional 30% boost when `max_lost > 0`, this binary trigger may be overly sensitive to transient loss events. The lack of loss-rate thresholds (e.g., only boost if loss > 5% of packets) or decay mechanisms (e.g., reduce boost if loss is old) means a single lost packet triggers sustained over-protection. Generation 3's approach (which also detects loss) achieves 1868.97 vs. 1977.84, suggesting that loss detection alone provides marginal benefit unless carefully integrated with other signals and time-decay mechanisms. The current best program's success despite this limitation indicates that the RTT-based protection dominates the scoring decision, making loss detection a secondary signal.

## Implementation Insights

- **Early-exit kprobe optimization with `any_enabled` flag check is critical for baseline parity and enables safe evolution**: The current best program (Generation 5) includes a loop that checks `any_enabled |= gf_configs[i].listener_mask` before processing any network data in the tcp_recvmsg kprobe. When all listeners are disabled (baseline configuration), this check returns immediately, ensuring zero overhead and matching the non-instrumented baseline (Generation 0, 1965.52). This architectural separation allows safe evolution—the networking infrastructure is fixed, but the policy (gf_configs, folio_cfg, bpf_score_fn) can be evolved without modifying the kprobe. The kprobe is conditionally compiled (`#if 1`), enabling complete disabling for pure LFU behavior. This pattern is replicated in all passing programs and appears essential for maintaining baseline performance while enabling dynamic network adaptation.

- **Fixed-point arithmetic with conditional branches avoids BPF signed division constraints and enables transparent debugging**: Generation 5's scoring function uses fixed-point multiplication/division (e.g., `(base_score * network_factor) / 100`) where network_factor is computed via conditional branches on RTT thresholds (100 = 1.0x, 125 = 1.25x, 150 = 1.5x). This approach is BPF-compatible and avoids the signed division trap that caught Generations 7 and 8. The network_factor variable is computed via simple comparisons (`if (srtt_ewma > 10000)`) rather than complex arithmetic, making the logic transparent and debuggable. The fixed-point representation (dividing by 100) is consistent across all calculations, reducing the risk of overflow or precision loss. This pattern is replicated in all passing programs and appears essential for reliable BPF compilation.

- **Per-folio metadata initialization via lazy loading in both folio_added and folio_accessed callbacks ensures consistency**: Generation 5 initializes per-folio metadata in folio_added via `vulcan_folio_init(bpf_ktime_get_ns())` and also includes lazy initialization in folio_accessed if metadata is missing. This dual-path initialization ensures that every tracked folio has valid timestamps and listener state, preventing null-pointer dereferences or stale data. The metadata map uses folio pointer as key (`u64 key = (u64)folio`), enabling O(1) lookups during eviction scoring. The lazy initialization in folio_accessed handles edge cases where a folio is accessed before being added to the list, ensuring robustness. This pattern is replicated in all passing programs and appears essential for correctness.

- **Vulcan listener dispatch layer abstractions enable policy evolution without modifying networking infrastructure**: The code includes `#include "vulcan_bpf/vulcan_feature.h"` which provides `vulcan_update_feature()` and accessor functions (`vulcan_get_ewma()`, `vulcan_get_max()`, etc.). This abstraction allows the scoring function to call `vulcan_get_ewma(GF_SRTT_US)` without knowing which map or listener state to access. The dispatch is controlled by `gf_configs[]` array, enabling per-feature listener configuration. This design allows evolution of scoring logic without modifying the listener infrastructure, reducing the risk of introducing bugs in the fixed networking code. The accessor functions safely return 0 for disabled listeners, enabling safe calls regardless of configuration. This pattern is replicated in all passing programs and appears essential for maintainability and safe evolution.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

# Actionable Recommendations for Future Program Mutations

1. **Implement adaptive RTT thresholds based on EWMA baseline drift detection**: The current fixed thresholds (5ms, 10ms) are static, but network conditions vary. Add a baseline RTT tracking mechanism: compute a long-term EWMA of SRTT_US with a low alpha (e.g., 50) to establish a "normal" RTT, then apply protection multipliers based on deviation from this baseline (e.g., 1.25x if current > baseline * 1.2, 1.5x if current > baseline * 1.5). This extends the proven RTT-threshold approach while adapting to workload-specific network characteristics, potentially improving performance across diverse network conditions without requiring manual tuning.

2. **Integrate PACKETS_OUT congestion signal with dynamic boost scaling based on cwnd utilization ratio**: The current program enables PACKETS_OUT EWMA but ignores it in scoring. Add a secondary congestion check in bpf_score_fn: compute `packets_out_ewma / snd_cwnd_ewma` (using safe unsigned arithmetic to avoid BPF division failures) and apply a scaled boost (e.g., 1.05x if ratio > 0.7, 1.15x if ratio > 0.9) to the network_factor. This leverages the already-enabled listener and provides a complementary signal to RTT for detecting window saturation, which is particularly valuable during congested workloads where the current program shows lower throughput than baseline.

3. **Refine per-folio heat scoring with workload-adaptive interval thresholds computed from interval_ewma distribution**: The current fixed thresholds (1s for hot, 10s for cold) may not match all workloads. Implement a two-pass approach: during the first 100 eviction cycles, collect interval_ewma statistics (min, max, median) in a small map, then compute dynamic thresholds as `median * 0.5` for hot and `median * 5` for cold. This builds on the proven per-folio EWMA tracking while adapting to workload-specific access patterns, potentially improving working-set retention by better distinguishing truly hot folios from moderately-accessed ones.

4. **Add time-decay to loss-triggered protection boost to prevent sustained over-protection after transient loss events**: The current 30% boost applies whenever `max_lost > 0`, which may persist indefinitely after a brief loss spike. Implement decay: track the timestamp of the last loss event and scale the boost by `exp(-(now - last_loss_ts) / 100ms)`, so the boost decays to ~37% after 100ms and ~5% after 300ms. This prevents loss signals from stale-locking the cache into overly conservative eviction, addressing the potential inefficiency where loss detection provides marginal benefit (Generation 3 vs. best program shows only -109 points difference despite loss detection).

5. **Implement per-folio access-rate normalization to prioritize recently-active folios over long-lived but infrequently-accessed ones**: The current base_score uses raw `access_count`, which biases toward folios that have been in cache longer regardless of recent activity. Replace with a recency-weighted access rate: `access_count * exp(-(now - last_access_ts) / 10s)`, which decays the score exponentially if a folio hasn't been accessed recently. This improves victim selection under memory pressure by preferring to evict old, cold folios even if they have high historical access counts, potentially improving the dual_small_vs_large throughput metric which currently shows higher variability (std: 154.26) than the congested workload.
