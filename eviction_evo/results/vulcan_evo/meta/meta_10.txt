# Program Evaluation Analysis

## Successful Algorithmic Patterns

- **Multi-layered network-aware scoring with conservative thresholds achieves consistent +0.15-0.6% improvement over baseline**: The current best program (Generation 8, score 4743.22) successfully implements a four-tier RTT protection strategy (>50ms: +50% bonus, >35ms: +37.5% bonus, >20ms: +25% bonus) combined with loss detection (+33% bonus), per-folio heat detection (interval EWMA <100ms: +5000), variance-based regularity detection (interval spread <50ms: +2000), and recency protection (age <5s: +3000, <30s: +1000). This layered approach outperforms the baseline (4217.68) by 525.54 points (12.4% improvement) and exceeds Generation 6 (4294.74) by 448.48 points (10.4% improvement) and Generation 7 (4462.83) by 280.39 points (6.3% improvement). The key insight is that each protection layer operates on a different dimension (network latency, access frequency, temporal locality, recency), and their combination creates a robust scoring space that adapts to diverse workload conditions without triggering BPF compiler constraints.

- **Dual interval tracking (MinMax + EWMA) for per-folio heat detection enables predictable access pattern recognition**: Generation 8's implementation tracks both `interval_minmax` (min/max inter-access intervals) and `interval_ewma` (exponential moving average of intervals) per folio, enabling two complementary detection mechanisms. The EWMA identifies hot folios with consistently short re-access intervals (<100ms: +5000 bonus), while the variance calculation (`interval_max - interval_min < 50ms`) identifies folios with highly regular, predictable access patterns (+2000 bonus). This dual-metric approach achieved 4743.22 vs. Generation 7's single-metric approach (4462.83, +280.39 points), demonstrating that variance-based regularity detection adds meaningful signal for workloads with periodic access patterns (e.g., LevelDB compaction scans, YCSB sequential phases). The implementation requires only two additional u64 fields per folio (min_val, max_val) beyond the EWMA value, making it memory-efficient.

- **Congestion window collapse detection as a secondary network protection signal complements RTT-based scoring**: Generation 9 (score 4566.55) adds explicit CWND collapse detection to the scoring function, recognizing that severe congestion (CWND near zero or below slow-start threshold) is a distinct network degradation signal separate from high RTT. While Generation 9's score (4566.55) is lower than Generation 8 (4743.22, -176.67 points), the feedback indicates the multi-layered protection strategy (RTT tiers, loss detection, CWND collapse, per-folio heat, recency) provides "robust performance across diverse workloads." This suggests that CWND collapse detection is a valid protection mechanism but may require careful threshold tuning to avoid over-protecting during transient congestion events. The pattern demonstrates that network-aware scoring benefits from multiple independent congestion signals rather than relying solely on RTT.

- **Early-exit kprobe guard with listener-mask checking maintains zero-overhead baseline compatibility while enabling incremental monitoring**: All successful programs (Generations 6-9) include a loop that checks `gf_configs[i].listener_mask` and returns immediately if no listeners are enabled, matching the baseline's behavior (4217.68). This architectural pattern allows the kprobe to remain attached without performance penalty when network monitoring is disabled, enabling seamless transition from baseline to network-aware mode. The implementation in Generation 8 explicitly documents this: "Baseline: when no listeners enabled, exit immediately — zero overhead. Matches initial_sampling (no kprobe work)." This design choice is critical because naive kprobe implementations that always execute full TCP metric extraction cause "throughput collapse" (as noted in the feedback for earlier failed attempts), whereas the guard-based approach maintains baseline throughput while adding only the cost of the listener update loop when enabled.

## Ineffective Approaches

- **Aggressive arithmetic-based RTT ratio calculations violate BPF signed division constraints and cause compilation failure**: Generations 2, 3, and 4 all attempted to implement sophisticated RTT-based scoring using division operations: Generation 2 used `(rtt_ewma * 100) / (rtt_min + 1)`, Generation 3 tried `(rtt_ewma - 15000) / 30000`, and Generation 4 used `(packets_out * 100) / cwnd`. All three failed with score 0.00 due to BPF compiler rejection of signed integer division at the point of use. The feedback explicitly states: "BPF compiler (clang-14) rejects signed integer division... BPF requires unsigned division; the expression must be rewritten using unsigned types or bit-shifts." This pattern demonstrates that while ratio-based scoring is theoretically sound (normalizing RTT relative to minimum or baseline), the BPF backend's lack of `sdiv` instruction support makes such approaches infeasible. The successful programs (Generations 6-9) avoid this entirely by using simple addition-based bonuses (`score += meta->access_count / 2` for division by constant 2, which compiles to bit-shift), proving that conservative additive scoring is both safer and sufficient.

- **Complex conditional scoring logic with multiple arithmetic branches exceeds BPF verifier complexity limits**: The failed programs (Generations 2-4) attempted to implement sophisticated heuristics with multiple division operations, conditional branches for pressure calculations, and ratio-based multipliers. The feedback for Generation 4 notes: "the design is sound (network-aware protection logic, per-folio heat tracking, LevelDB index block preservation), but the implementation violates BPF backend constraints and cannot be validated functionally." This indicates that even theoretically correct designs fail if they exceed the verifier's instruction count or path explosion limits. The successful programs maintain scoring functions under ~50 lines of straightforward C with simple if-then-add patterns, avoiding nested conditionals and complex arithmetic. Generation 8's scoring function, for example, uses a flat sequence of independent protection checks (RTT tiers, loss detection, heat detection, variance detection, recency) rather than nested conditionals or interdependent calculations, keeping the verifier's path count manageable.

- **Enabling all network listeners without selective tuning adds overhead without proportional benefit and may destabilize scoring**: While not explicitly tested in the provided summaries, the pattern across successful programs shows selective listener enablement: Generation 8 enables only three listeners (GF_SRTT_US with EWMA, GF_SND_CWND with EWMA, GF_LOST with MINMAX, GF_INTER_ARRIVAL with EWMA) while leaving 12 others disabled. This selective approach contrasts with the failed programs' attempts to use more comprehensive feature sets. The principle is evident in the feedback: "The kprobe overhead is mitigated by an early-exit check that disables monitoring when no listeners are enabled, matching baseline performance." Enabling unnecessary listeners increases kprobe execution time and map update frequency, potentially causing the "throughput collapse" mentioned in earlier feedback. The successful programs' minimal listener set (3-4 of 16 features) achieves the performance gain with lower overhead than a comprehensive monitoring approach would incur, suggesting that selective feature tuning is more effective than exhaustive monitoring.

## Implementation Insights

- **Vulcan listener framework's declarative configuration enables safe, verifiable network-aware scoring without architectural refactoring**: The current best program (Generation 8) leverages the Vulcan abstraction layer through the `gf_configs[]` array, which declaratively specifies which listeners are active for each feature and their parameters (e.g., `[GF_SRTT_US] = { .listener_mask = VULCAN_LISTENER_EWMA, .ewma_alpha = 200 }`). This design separates policy logic (the scoring function in `bpf_score_fn`) from infrastructure (map management, kprobe dispatch, listener updates). The scoring function accesses network metrics via simple accessor functions (`vulcan_get_ewma(GF_SRTT_US)`, `vulcan_get_max(GF_LOST)`) that safely return 0 if the listener is disabled, eliminating the need for manual map lookups or feature dispatch logic. This abstraction is critical for BPF safety: it ensures that the scoring function remains simple and verifiable, avoiding the complex arithmetic and conditional logic that caused Generations 2-4 to fail. The framework also enables incremental evolution: new listeners can be enabled by modifying `gf_configs[]` without touching the scoring function, and new scoring logic can be added without modifying the infrastructure.

- **Per-folio metadata with dual-metric interval tracking (EWMA + MinMax variance) provides multi-dimensional heat signals without state explosion**: Generation 8's implementation stores `meta->interval_ewma.value` (EWMA of inter-access intervals) and `meta->interval_minmax` (min/max intervals) per folio, enabling two complementary detection mechanisms with minimal memory overhead (two u64 fields per folio). The EWMA captures temporal locality (hot folios with consistently short intervals), while the variance calculation identifies predictable access patterns (low spread = regular, cacheable behavior). This dual-metric approach is more informative than raw access counts alone because it captures both frequency and regularity: a folio accessed 100 times in 1 second with consistent 10ms intervals is hotter and more predictable than one accessed 100 times over 1 hour with irregular intervals. The implementation updates these metrics via `vulcan_folio_on_access()` on each access, which is called from the `folio_accessed` hook. The scoring function then uses these metrics to apply bonuses: `if (interval_ewma < 100000000) score += 5000` for hot folios, and `if (variance < 50000000) score += 2000` for regular patterns. This approach achieved 4743.22 vs. Generation 7's single-metric approach (4462.83), demonstrating that variance-based regularity detection adds 280.39 points (6.3% improvement).

- **Conservative threshold-based bonuses with fixed additive increments avoid arithmetic complexity while maintaining predictability and correctness**: The current best program uses simple comparisons followed by fixed or proportional bonuses: `if (rtt_ewma > 50000) score += meta->access_count / 2` (division by constant 2, compiled to bit-shift), `if (lost_max > 0) score += meta->access_count / 3`, `if (interval_ewma < 100000000) score += 5000`, `if (variance < 50000000) score += 2000`, `if (age < 5000000000) score += 3000`. These patterns compile reliably because they avoid division-by-variable operations and use only simple arithmetic that the BPF backend supports. The thresholds are conservative (RTT >50ms for +50% bonus, >35ms for +37.5%, >20ms for +25%) rather than aggressive multipliers, ensuring that the policy does not over-protect during transient network degradation. The scoring function remains under ~50 lines of straightforward C, keeping the verifier's path count manageable. This simplicity is a feature: it ensures the policy is predictable, verifiable, and maintainable, contrasting sharply with the failed programs' attempts at sophisticated ratio-based calculations.

- **Recency-based protection with age-tiered bonuses complements frequency-based scoring to capture working set dynamics**: Generation 8 adds recency protection with two tiers: `if (age < 5000000000) score += 3000` (< 5 seconds) and `if (age < 30000000000) score += 1000` (< 30 seconds). This recency component recognizes that recently accessed folios are likely in the active working set, even if their cumulative access count is moderate. The age calculation uses `u64 now = bpf_ktime_get_ns()` and `s64 age = (s64)(now - meta->last_access_ts)`, which is updated on each access via `vulcan_folio_on_access()`. The recency bonuses are modest (+3000 and +1000) compared to the base LFU score (which can be hundreds or thousands depending on access count), ensuring that recency acts as a tie-breaker rather than dominating the scoring. This multi-dimensional approach (frequency + network conditions + heat + variance + recency) achieved 4743.22, outperforming the baseline (4217.68) by 525.54 points (12.4% improvement). The pattern demonstrates that adding recency awareness to LFU-based scoring improves cache retention for workloads with temporal locality, such as YCSB's read-heavy phases where recently accessed records are likely to be re-accessed soon.
