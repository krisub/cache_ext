<DESCRIPTION>
The current CWND recovery detection reduces protection bonuses during recovery, but this approach has caused a performance regression (5207.70 vs 5667.51 in the best prior). The recommendation suggests a different approach: detect sustained congestion (when CWND is stuck below historical minimum while losses persist) and ADD an additional stacking bonus rather than modulating existing bonuses.

This edit implements dual-metric sustained congestion detection that:
1. Uses both CWND collapse ratio (EWMA < MIN * 1.3) AND loss persistence (MAX > 0) to identify true sustained congestion
2. Applies an ADDITIONAL +1000 bonus that stacks additively with existing loss-triggered bonuses
3. Removes the cwnd_recovering logic that was reducing bonuses (causing the regression)
4. Uses conservative 1.3x ratio threshold to avoid false positives

The key difference: instead of reducing protection during recovery (which hurt performance), we increase protection during sustained congestion by stacking bonuses. This provides more reliable working-set expansion identification without the regression.
