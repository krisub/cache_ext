cwnd_ratio_sustained_congestion_detection
</NAME>

<DESCRIPTION>
This edit implements sustained congestion detection using CWND-to-minimum-CWND ratio monitoring with secondary loss amplification bonuses. The approach:

1. **Enable MINMAX listener for GF_SND_CWND**: Currently only EWMA is enabled. Adding MINMAX allows tracking the historical minimum congestion window, which serves as a baseline for detecting sustained degradation.

2. **Ratio-based sustained congestion signal**: When `vulcan_get_ewma(GF_SND_CWND) < vulcan_get_min(GF_SND_CWND) * 1.4`, the connection is experiencing sustained congestion (CWND stuck significantly below its historical minimum). This is more reliable than transient loss signals alone because it captures persistent congestion state rather than momentary spikes.

3. **Stacked amplification bonuses**: During sustained congestion, apply an additional +2000 bonus that stacks with existing loss-triggered bonuses in the recency protection tiers. This provides graduated protection: normal conditions get base protection, transient loss gets moderate amplification, and sustained congestion (loss + low CWND ratio) gets maximum protection.

The 1.4x threshold is conservative - it triggers when CWND is more than 30% below historical minimum, indicating the connection is in recovery mode and hasn't restored capacity. This avoids the overly aggressive protection that caused regression in Gen 19 while still distinguishing between brief loss events and sustained degradation.

By stacking with jitter-aware protection already present in the current policy, this creates a multi-signal approach that adapts to different network conditions: RTT elevation, jitter volatility, transient loss, and sustained congestion.
</DESCRIPTION>
