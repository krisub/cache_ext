<DESCRIPTION>
The current program's performance regression (1873.98 vs 2184.76 best) stems from the complex loss time-decay logic that adds overhead without clear benefit. The recommendation suggests calibrating the recency-weighted score calculation to better distinguish folios with similar access counts but different temporal localities.

The key insight is that the current recency calculation treats all accesses within 1 second identically (50% boost), missing the critical distinction between a folio accessed 0.1s ago (extremely hot) versus 0.9s ago (warm). Similarly, the 1-10 second window uses coarse 1-second granularity.

This change:
1. **Removes the complex loss time-decay mechanism** (global `last_loss_ts` variable and decay calculation) that hurt performance, reverting to the simpler best-performing approach
2. **Introduces finer-grained recency weighting** within the critical <1 second window using 100ms buckets (80% boost at <100ms, decaying to 50% at 1s)
3. **Maintains proven network-aware protection** from the best program (simple MINMAX loss check, EWMA RTT/PACKETS_OUT)

This provides better temporal resolution for hot working-set folios while avoiding the overhead of per-eviction loss timestamp tracking. The more aggressive initial boost (80% vs 50%) for extremely recent accesses (<100ms) better protects the active working set during network-bound operations, while the smoother decay curve maintains differentiation across the full 10-second window.
