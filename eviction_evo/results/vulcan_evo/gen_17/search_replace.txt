loss_decay_with_rolling_window
</NAME>

<DESCRIPTION>
The current loss detection uses `vulcan_get_max(GF_LOST)`, which tracks the maximum loss value ever observed. This causes sustained over-protection even after the network recovers and loss clears.

The recommendation suggests time-decay: stale loss signals should gradually lose their protective effect. Since we cannot add new maps to track timestamps, we use the RollingWindow listener (already available in vulcan_bpf) instead of MinMax for GF_LOST. This naturally provides recency-aware loss tracking:

- Recent loss (latest window entries non-zero) → full 15% boost
- Older loss (earlier window entries had loss, but latest is zero) → partial/no boost
- Clean period (no loss in entire window) → no boost

We check both the most recent loss value and earlier entries with partial weight to implement approximate exponential decay using window position as a proxy for age. A window size of 4-6 entries gives us roughly 100-150ms of history depending on packet frequency.

This change shifts from binary (loss ever detected) to continuous (how recent was the loss), preventing stale loss signals from indefinitely locking the cache into overly conservative eviction.
</DESCRIPTION>
