Looking at the current performance metrics, I notice:
- **Throughput: 180.06 ops/sec** (very low for a networked database)
- **Read latency: 44ms average, 280ms p99** (extremely high)

The root cause is likely **aggressive eviction** of the working set. The current policy protects folios only if:
1. They're "hot" (3+ accesses) AND recently accessed (100ms), OR
2. They're owned by the active DB PID AND within 1s window

This is too strict. For a networked LevelDB workload:
- TCP request-response cycles can exceed 100ms easily
- Database working set can span seconds
- We're evicting folios that are still part of active read patterns

**Key insight:** Network-aware DBs need to **protect the stable working set longer** and use **frequency-based (LFU) tiers** rather than pure recency. The access_tier field exists but isn't used in eviction decisions.

## Proposed improvements:

1. **Increase RECENT_ACCESS_NS** to capture full request-response cycle (500ms instead of 100ms)
2. **Use access_tier in eviction logic** - preserve warm/hot folios more aggressively
3. **Extend WORKING_SET_NS** window for the active DB (folios accessed within 5s are protected)
4. **Add a frequency decay mechanism** to prevent stale hot classifications
5. **Boost cold folio protection** slightly during active network sessions (cache coherence matters)

This evolution improves LevelDB throughput by:

1. **Extended recency window (500ms)** - TCP round-trips and LevelDB compaction routines take time; 100ms is too aggressive.
2. **Frequency-tier-based protection** - Warm (2+ accesses) and hot (3+ accesses) folios get longer protection windows, mimicking LFU behavior.
3. **Longer working set window (5s)** - The active DB's working set should persist across multiple request batches.
4. **Decay mechanism** - Access count slowly decreases if a folio hasn't been touched in 2s, preventing stale hot classifications.
5. **Session-aware cold protection** - During active network sessions, even cold folios get a small grace period, improving cache hit ratio during burst workloads.

These changes shift the policy from "keep only the hottest recent pages" to "keep the stable working set + hot pages + some cold filler", which is better aligned with database access patterns.

static int bpf_evict_cb(int idx, struct cache_ext_list_node *node)
{
    u64 now = bpf_ktime_get_ns();
    u64 key = (u64)node->folio;

    struct net_folio_metadata *meta =
        bpf_map_lookup_elem(&folio_metadata_map, &key);

    // No metadata → unknown folio → evict
    if (!meta)
        return CACHE_EXT_EVICT_NODE;

    if (folio_test_dirty(node->folio) || folio_test_writeback(node->folio))
        return CACHE_EXT_CONTINUE_ITER;

    bool is_active_db   = (meta->owner_pid == active_db_pid) && (active_db_pid != 0);
    bool recently_used  = (now - meta->last_access_ts) < RECENT_ACCESS_NS;

    if (is_hot && recently_used)

    if (session_active && is_active_db && in_working_set)
        return CACHE_EXT_CONTINUE_ITER;

    // Protect any recently accessed folio
    if (recently_used)
        return CACHE_EXT_CONTINUE_ITER;

    return CACHE_EXT_EVICT_NODE;
