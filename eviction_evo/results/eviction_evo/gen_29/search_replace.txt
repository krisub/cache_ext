<DESCRIPTION>
The current program uses a fixed 2ms jitter threshold regardless of RTT, which can cause false positives on high-latency connections.

The analysis of prior programs shows the best performance (2182.27) was achieved without the working set stability tracking that's currently hurting performance (2087.32 vs 2182.27).

The recommended improvement is to implement adaptive jitter threshold scaling based on RTT:
- At low RTT (e.g., 1ms), a 2ms jitter is severe → trigger pressure detection
- At high RTT (e.g., 100ms+), a 2ms jitter is negligible → don't trigger pressure detection

Formula: threshold = 2ms * (RTT / 100ms), clamped to [1ms, 4ms]

This makes congestion detection context-aware, reducing false positives during high-latency periods and preventing unnecessary eviction protection that can hurt cache efficiency.

Additionally, remove the working set stability tracking which is adding complexity without benefit (current 2087.32 is worse than previous 2182.27).
</DESCRIPTION>

// -- Helper: get dynamic hot threshold based on working set stability --------
static __always_inline u32 get_hot_threshold_by_stability(void)
{
    u32 stats_key = 0;
    struct eviction_scan_stats *stats =
        bpf_map_lookup_elem(&eviction_scan_stats_map, &stats_key);

    if (!stats || stats->protected_in_window == 0)
        return HOT_ACCESS_THRESHOLD;

    // Calculate stability ratio: (recently accessed in window / total in window) * 100
    u32 stability = (stats->recent_in_window * 100) / stats->protected_in_window;

    // If working set is stable (>80% of protected folios recently accessed),
    // lower the hot threshold by 1 to be more protective
    if (stability > STABILITY_HIGH_RATIO) {
        // Lower threshold promotes warm folios to "hot" protection
        return (HOT_ACCESS_THRESHOLD > 1) ? (HOT_ACCESS_THRESHOLD - 1) : 1;
    }

    return HOT_ACCESS_THRESHOLD;
}

// -- Helper: compute adaptive jitter threshold based on RTT percentile -------
// Scale 2ms baseline by (RTT / 100ms), clamped to [0.5x, 2.0x] → [1ms, 4ms]
static __always_inline u32 get_adaptive_jitter_threshold(void)
{
    // If RTT is 0, use baseline threshold
    if (net_srtt_us == 0)
        return JITTER_THRESHOLD_BASE_US;

    // Calculate threshold = 2ms * (net_srtt_us / 100ms)
    // This makes jitter interpretation context-aware:
    // - Low RTT (1ms): threshold = 2ms * (1ms / 100ms) = 20us (very strict)
    // - Medium RTT (10ms): threshold = 2ms * (10ms / 100ms) = 200us
    // - High RTT (100ms+): threshold = 2ms * (100ms+ / 100ms) = 2ms+ (loose)
    u64 scaled = ((u64)net_srtt_us * JITTER_THRESHOLD_BASE_US) / 100000;

    // Clamp scaling ratio to [0.5, 2.0] to avoid extreme thresholds
    if (scaled < 1000000) scaled = 1000000;    // 0.5x minimum → 1ms
    if (scaled > 4000000) scaled = 4000000;    // 2.0x maximum → 4ms

    return (u32)scaled;
}
