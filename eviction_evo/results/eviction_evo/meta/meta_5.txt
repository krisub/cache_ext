# Program Evaluation Analysis

## Successful Algorithmic Patterns

- **Multi-factor scoring with network-aware multipliers**: The current best program (Generation 3, score 2162.27) achieves the highest performance by combining age-based scoring (0-100 range with tiered thresholds), frequency penalties for hot/warm/cold tiers, and network-adaptive multipliers (0.75x under pressure, 0.5x during bursts). This outperforms the simpler fixed-threshold approaches in Generations 0 and 1 (1907.18 and 1932.40 respectively), demonstrating that coupling eviction scoring directly to network conditions yields ~12-13% improvement over time-window-only strategies.

- **Burst detection with inter-arrival timing**: The current best program detects request bursts via inter-arrival packet timing (< 10ms threshold) and applies protective 0.5x score multipliers to recently-accessed folios during active sessions. This mechanism successfully preserves working sets during congested workloads, contributing to the exceptional congested-scenario throughput of 3152.17 (compared to 3037.95 in Generation 1 and 3138.73 in Generation 4), while maintaining reasonable P99 latency of 41.2ms.

- **Adaptive eviction thresholds based on session state**: The current best program dynamically adjusts the eviction threshold (base 60, raised to 70 under pressure, lowered to 40 when idle, +10 during bursts) rather than applying fixed protection windows. This state-aware approach outperforms the fixed 100ms/1s/5s window strategy in Generation 0, allowing aggressive eviction of truly cold data during idle periods while protecting working sets during active network sessions.

- **Comprehensive network pressure detection**: The current best program detects network pressure through multiple independent indicators (packet loss, cwnd pressure ratio > 2, jitter > 2ms, RTT > 1ms), applying pressure-aware scoring multipliers only when multiple conditions align. This multi-signal approach prevents false positives that could over-retain cache, contributing to the strong small-vs-large throughput of 1645.52 (highest among all evaluated programs).

## Ineffective Approaches

- **Undefined constant references causing compilation failure**: Generation 2 (score 0.00) failed entirely due to referencing `HOT_ACCESS_THRESHOLD` without defining it as a constant, and calling `bpf_cache_ext_list_del(folio)` with incorrect argument count. While Generation 0 achieved 1907.18 and Generation 1 achieved 1932.40, both underperform the current best by 12-13%, indicating that static time windows cannot adapt sufficiently to varying network conditions and workload patterns.

The following are actionable recommendations for the next program generations:

# Actionable Recommendations for Future Program Mutations

1. **Implement adaptive access count thresholds based on network conditions**
   The current best program uses fixed thresholds (HOT_ACCESS_THRESHOLD=3, warm at 2) for tier classification, but network pressure and burst conditions could warrant dynamic adjustment. During high-pressure periods, lower the hot threshold to 2 (treating more folios as hot and thus protective), and during idle periods, raise it to 4 to aggressively evict folios with fewer accesses. This would extend the successful multi-factor scoring approach by making tier classification itself network-aware, potentially improving both congested throughput (by protecting more working set during pressure) and small-vs-large throughput (by aggressive eviction during idle).

2. **Introduce a secondary "promotion list" for folios that survive multiple eviction scans**
   The current program uses a single main_list with MRU-based ordering, but folios that repeatedly avoid eviction during scans could be explicitly promoted to a higher-priority tier. Implement a two-tier list structure where folios that survive 3+ consecutive eviction scans are moved to a "survivor_list" with a permanently elevated score multiplier (0.5x base score). This builds on the successful burst-protection mechanism and could reduce thrashing during sustained congestion by 2-3%, as evidenced by the current best program's exceptional 3152.17 congested throughput.

3. **Refine burst detection to use packet count velocity rather than just inter-arrival timing**
   The current burst detection relies solely on inter-arrival time (< 10ms), but this can miss sustained high-frequency workloads. Add a secondary burst signal: if net_recv_count increases by more than 10 packets within a 100ms window, classify as "sustained burst" and apply a more aggressive 0.4x multiplier (vs. current 0.5x) to recently-accessed folios. This would complement the existing inter-arrival detection and better distinguish between transient spikes and sustained load, potentially improving P99 latency during congested scenarios.

4. **Implement score decay based on folio size to favor small-folio retention**
   The current program achieves strong small-vs-large throughput (1645.52) but doesn't explicitly account for folio size in scoring. Add a size-based score adjustment: reduce the eviction score by 10% for folios smaller than 4KB and increase it by 10% for folios larger than 64KB. This directly targets the small-vs-large workload variance and aligns with the insight that sophisticated scoring prevents "sticky" behavior—small folios should be evicted more aggressively to make room for larger working sets, improving cache efficiency by 2-3%.

5. **Extend network pressure detection to include receive window (rcv_wnd) saturation**
   The current program detects pressure via loss, cwnd ratio, jitter, and RTT, but doesn't monitor receive window exhaustion. Add a fifth pressure signal: if net_rcv_wnd is below 64KB (indicating receiver buffer pressure), apply the 0.75x protective multiplier. This would catch a class of network congestion (receiver-side backpressure) not currently detected, potentially improving robustness during asymmetric workloads and preventing over-eviction when the bottleneck is on the remote end rather than local congestion.
