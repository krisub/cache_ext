# Program Evaluation Analysis

## Successful Algorithmic Patterns

- **Single unified list with tiered metadata classification outperforms multi-list architectures**: The current best program (Generation 2: network_aware_lfu_working_set, score 191.02 ops/sec) uses a single `main_list` with per-folio metadata tracking access counts and timestamps, achieving superior performance compared to attempted multi-tier segregated list designs (Generation 4 failed to load with BPF verifier errors). The unified approach eliminates list management complexity while maintaining tier classification through metadata fields (`access_tier`, `access_count`), reducing verification overhead and enabling more efficient iteration.

- **Frequency decay mechanism with overlapping protection windows enables balanced recency-frequency tradeoffs**: The best program implements decay-based access count management (decrementing `access_count` after 2 seconds of inactivity) combined with three overlapping protection windows (500ms recent-access, 5s working-set, 200ms cold-session grace period). This multi-layered approach achieved 191.02 ops/sec compared to the initial program's 180.06 ops/sec (+6.1% improvement), demonstrating that frequency signals combined with time-windowed recency provide better cache retention decisions than simple recency-only policies.

- **Network-aware working set protection with tier-aware conditional logic prevents overly conservative eviction**: The best program protects active database working sets through conditional logic that checks both network session state (`session_active && is_active_db`) and access tier (`is_warm && in_working_set`), while still allowing cold folios a grace period (200ms) rather than blanket protection. This balanced approach achieved 191.02 ops/sec with p99 latency of 271ms, compared to the initial program's 279.6ms p99 latency (-3.1% improvement), indicating that tier-aware conditional protection reduces unnecessary cache retention without sacrificing working set preservation.

- **Proper folio lifecycle management with explicit list deletion prevents kernel memory corruption**: The best program correctly implements `folio_evicted` callback with explicit `bpf_cache_ext_list_del(folio)` before metadata cleanup, preventing dangling pointers in the list structure. This implementation detail, documented in the code comment about "GPF in userspace," ensures stable execution and correct program validation, contrasting with Generation 1 and Generation 3 which had variable declaration mismatches that prevented compilation entirely.

## Ineffective Approaches

- **Multi-tier segregated list architectures introduce verification complexity without performance gains**: Generation 4 (multi_tier_segregated_lists) attempted to implement three separate lists (`hot_list`, `warm_list`, `cold_list`) with tier-based promotion/demotion callbacks but failed to load with BPF verifier errors regarding function argument type mismatches in `bpf_cache_ext_list_sample()`. The architectural design was sound, but the implementation complexity of managing three separate lists and their promotion logic exceeded the verifier's ability to validate the code, resulting in a score of 0.00 compared to the best program's 191.02.

- **Variable declaration mismatches between declared and used list handles cause compilation failures**: Generations 1 and 3 both declared three list handles (`hot_list`, `warm_list`, `cold_list`) but referenced an undeclared `main_list` variable throughout all callback functions, resulting in 7 compilation errors each and scores of 0.00. This pattern demonstrates that inconsistent variable naming between declaration and usage, even with sound eviction logic, completely prevents program execution and eliminates any performance benefit from the underlying algorithm.

- **Overly conservative folio protection policies increase p99 latency without throughput gains**: The initial program (Generation 0, score 180.06 ops/sec) achieved only 180.06 ops/sec with p99 latency of 279.6ms (6.3x average latency), suggesting that its protection heuristics were retaining too many folios in cache, causing memory pressure and occasional cache misses. The best program's 191.02 ops/sec with 271ms p99 latency (+6.1% throughput, -3.1% p99 latency) indicates that the frequency decay mechanism and more selective tier-aware protection windows reduce unnecessary retention while maintaining working set preservation.

- **API signature mismatches between evolved code and BPF helper functions prevent program loading**: Generation 4 failed with a BPF verifier error indicating that the ratio parameter `10` passed to `bpf_cache_ext_list_sample()` was a scalar but the verifier expected a frame pointer, revealing a mismatch between the evolved code's API usage and the actual helper signatures in `cache_ext_lib.bpf.h`. This demonstrates that even architecturally sound designs fail if the implementation doesn't match the actual BPF helper function signatures.

## Implementation Insights

- **Single unified list with metadata-driven tiering eliminates list management overhead while preserving tier semantics**: The best program declares a single `static u64 main_list` and uses per-folio metadata fields (`access_tier`, `access_count`) to classify folios into cold/warm/hot tiers, rather than maintaining three separate lists. This approach reduces the number of list operations (add/delete/move) required during eviction iteration, as all folios are scanned from a single list with tier decisions made in the callback based on metadata, rather than requiring cross-list promotions or demotions. The callback function `bpf_evict_cb` evaluates tier membership dynamically (`is_hot = meta->access_count >= HOT_ACCESS_THRESHOLD`) rather than relying on list membership, enabling more flexible tier transitions without list reorganization.

- **Frequency decay with time-windowed access count management provides adaptive recency-frequency balance**: The best program implements decay logic in `folio_accessed` that decrements `access_count` if the folio hasn't been touched for `FREQ_DECAY_NS` (2 seconds), then increments it on each access. This creates a self-adjusting frequency signal where frequently-accessed folios maintain high counts while stale folios gradually decay, enabling the eviction callback to distinguish between genuinely hot folios and those that were once hot but are now cold. The tier classification (`access_tier = 2` for `access_count >= 3`, tier 1 for `>= 2`) then uses this decayed frequency signal to make eviction decisions, combining recency (500ms window) with frequency (decay-adjusted access count) in a unified framework.

- **Overlapping time windows with conditional tier-aware logic enable nuanced protection without blanket retention**: The best program uses four distinct time windows (500ms recent-access, 5s working-set, 200ms cold-session grace, 2s decay) combined with conditional logic that checks multiple factors: `if (is_hot && recently_used) return CONTINUE_ITER` protects hot folios only if recently accessed, while `if (session_active && is_active_db && time_since_access < COLD_SESSION_GRACE_NS) return CONTINUE_ITER` gives cold folios a grace period only during active sessions. This multi-layered approach prevents the overly conservative protection seen in Generation 0 (which achieved only 180.06 ops/sec) by ensuring that protection is conditional on multiple factors rather than applying blanket retention rules.

- **Explicit folio lifecycle management with list deletion before metadata cleanup prevents kernel corruption**: The best program's `folio_evicted` callback explicitly calls `bpf_cache_ext_list_del(folio)` before deleting metadata, with a code comment explaining that this prevents "dangling folio pointer in main_list, causing kernel memory corruption (GPF in userspace)." This implementation detail ensures that the list structure remains consistent even after the folio is evicted, preventing the kernel from attempting to access freed memory through stale list pointers. The callback structure (`del → metadata_delete → bump_counter`) establishes a clear ordering that prevents race conditions between the eviction iterator and the metadata cleanup.

# Actionable Recommendations for Future Program Mutations

1. **Implement adaptive frequency decay with session-aware decay rates**: The current best program uses a fixed 2-second decay window, but network sessions have variable activity patterns. Introduce session-aware decay that slows decay (e.g., 5s window) when `session_active && is_active_db` is true, and accelerates decay (e.g., 1s window) during idle periods. This builds on the successful frequency decay mechanism while making it responsive to network state, potentially improving p99 latency by reducing unnecessary evictions during bursty workloads that the evaluation feedback identified as problematic.

2. **Extend the working-set protection window dynamically based on access frequency**: The current 5-second working-set window is static, but high-frequency folios (access_count >= 5) may benefit from extended protection. Introduce a tiered working-set window where `is_hot` folios get a 7-second window, `is_warm` folios get 5 seconds, and `is_cold` folios get 3 seconds, all while maintaining the existing tier-aware conditional logic. This leverages the successful metadata-driven tiering approach to provide more nuanced protection without adding list management complexity.

3. **Add a "scan detection" heuristic to prevent sequential scan pollution**: Implement a helper function that detects when a folio's `folio_index` is sequential to the previously accessed folio (within the same inode), and if so, cap its `access_count` at 1 regardless of actual access frequency. This prevents sequential scans (common in database full-table scans) from polluting the cache by artificially inflating access counts, while preserving the frequency decay mechanism for genuinely reused folios. This addresses a common cache eviction challenge without requiring multi-list architecture.

4. **Refine the cold-session grace period with access-count-aware thresholds**: The current 200ms grace period applies uniformly to all cold folios during active sessions, but the evaluation noted this "may be insufficient for bursty workloads." Replace the fixed grace period with a conditional: `if (time_since_access < COLD_SESSION_GRACE_NS && meta->access_count >= 1)` to give grace only to cold folios that have been accessed at least once, while immediately evicting never-accessed folios. This maintains the successful multi-layered protection approach while reducing unnecessary retention of truly cold data.

5. **Introduce a "recency boost" mechanism that temporarily elevates access_count on recent accesses**: When a folio is accessed, add a temporary boost: `meta->access_count += 2` instead of `+= 1` if `time_since_access < RECENT_ACCESS_NS`, then decay this boost faster (e.g., decay by 2 instead of 1 after FREQ_DECAY_NS). This creates a "spike" in the frequency signal for recently-touched folios, improving their protection during the critical 500ms window while still allowing them to decay naturally. This extends the successful frequency decay mechanism with a recency-aware amplification that could improve both throughput and p99 latency by better protecting working-set folios during bursty access patterns.
