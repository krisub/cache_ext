<DESCRIPTION>
The current program uses a fixed 2-second frequency decay window (FREQ_DECAY_NS) regardless of network session state. However, network workloads exhibit bursty access patterns where:

1. **During active sessions**: Requests arrive in bursts with variable inter-arrival times. A folio accessed 1.5 seconds ago might still be part of the active working set, but the fixed 2s decay window causes premature decay and eviction.

2. **During idle periods**: Folios that haven't been touched should decay faster to make room for new working sets.

The evaluation feedback identified p99 latency issues (271ms), suggesting that the policy is evicting folios that are still needed by bursty workloads.

**Solution**: Implement adaptive decay rates that respond to network state:
- When `session_active && is_active_db`: Use a **longer decay window (5s)** to preserve frequency signals during bursty activity
- When `!session_active` (idle): Use a **shorter decay window (1s)** to quickly age out stale folios

This builds on the successful frequency decay mechanism from the second program (which scored 183.16) while making it responsive to network state. By slowing decay during active sessions, we reduce unnecessary evictions during bursts. By accelerating decay during idle periods, we free cache space faster for new workloads.

Additionally, I'll add a **recency boost mechanism** (inspired by the second program's successful boost approach) that was removed in the current version. When a folio is accessed within a tight 50ms window, we add extra to its access_count to create a frequency spike. This helps bursty patterns stay protected.

These changes directly address the p99 latency problem by ensuring that working-set folios aren't evicted mid-burst due to overly aggressive decay.
</DESCRIPTION>
