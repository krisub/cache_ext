<DESCRIPTION>
The current best program uses a fixed 2-second frequency decay window (FREQ_DECAY_NS), which doesn't adapt to network activity patterns. During active database sessions with bursty workloads, this fixed decay can prematurely downgrade the access_count of folios that are part of the working set but haven't been touched in the last 2 seconds. This leads to unnecessary evictions during request bursts, contributing to the p99 latency spikes observed in the evaluation.

The proposed improvement implements session-aware adaptive decay:

1. **Slow decay during active sessions**: When `session_active && is_active_db` is true, extend the decay window to 5 seconds. This protects the working set during active request handling, as folios that were recently part of serving requests won't have their frequency artificially reduced.

2. **Fast decay during idle periods**: When the session is idle (no recent packets), use a shorter 1-second decay window to more aggressively reclaim cold pages that are no longer part of any active workload.

3. **Maintain existing decay logic**: The decay still only applies when a folio is accessed again after the decay window, preserving the frequency-based eviction semantics while making them network-aware.

This builds on the successful frequency decay mechanism in the current best program while making it responsive to network state. The adaptive approach should reduce p99 latency by preventing premature evictions during bursty workloads, while maintaining aggressive reclamation during idle periods to keep the cache fresh.
</DESCRIPTION>
