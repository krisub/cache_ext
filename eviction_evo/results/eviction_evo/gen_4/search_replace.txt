Looking at the performance metrics:

**Current state:**
- Combined score: 1932.40
- dual_small_vs_large: 1416.81 throughput (down 35.72 from 1452.53), p99: 61.3ms (up 11.4ms)
- dual_congested: 3037.95 throughput (up 261.83), p99: 43.6ms (down 3.6ms)

The current program sacrifices dual_small_vs_large performance to improve dual_congested. The harmonic mean is sensitive to both workloads equally, so we're penalized for the small_vs_large degradation.

**Root cause analysis:**
The current approach is too aggressive with adaptive window expansion:
- Burst detection triggers a 1.5x expansion of already-adaptive windows during high request rates
- Network pressure triggers another 1.5x expansion
- Combined effect: protecting too many pages during the fast reader's burst phase in dual_small_vs_large

**Key insight:** In dual_small_vs_large, the fast reader creates natural bursts, but this shouldn't protect *all* pages—we still need aggressive eviction of large write pages. The "hot" classification via `access_count` already provides working set protection without needing time-window inflation.

**Proposed strategy:**
1. **Remove burst-based window expansion** — bursts just indicate high request rate; real working set pages are already protected via access frequency
2. **Reduce congestion protection multiplier** — use 1.25x instead of 1.5x for pressure (less aggressive)
3. **Lower base time constants** — reduce both BASE_RECENT_NS and BASE_WORKING_SET_NS to favor faster eviction in latency-sensitive workloads
4. **Tighten jitter threshold** — only treat extreme jitter (>2ms) as pressure indicator

**Rationale for changes:**

1. **Removed burst detection**: Bursts naturally lead to higher access counts on hot folios, providing working set protection without time-window inflation. This allows aggressive eviction of cold/infrequent pages, benefiting the small_vs_large workload where we need to evict large write pages quickly.

2. **Reduced base time constants** (50ms→30ms, 500ms→300ms): More aggressive eviction baseline favors throughput in latency-sensitive scenarios. The adaptive scaling still protects during actual congestion.

3. **Lowered RTT scaling factor** (÷10 → ÷20): Reduces how much RTT inflates protection windows, letting natural access frequency drive decisions instead.

4. **Reduced congestion multiplier** (1.5x → 1.25x): Pressure detection still provides some protection, but less aggressive, balancing both workloads.

5. **Increased jitter threshold** (1ms → 2ms): Only extreme jitter now triggers congestion-level protection, making the system more selective about when to be conservative.

These changes should recover the dual_small_vs_large throughput lost to over-protection while maintaining the improvements gained in dual_congested through smarter network-aware logic (access frequency + selective RTT/loss protection rather than time-window inflation).
